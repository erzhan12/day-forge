# R06: один пользовательский часовой пояс

Статус на 10 октября 2026 года: реализовано и проверено локально. Этапы R00–R05 и исправление диалога удаления сохранены. Изменения находятся в рабочем дереве, коммит и публикация не выполнялись.

## Что изменилось

Сохранённый `UserScheduleSettings.time_zone` определяет местный день и часы приложения. Пояс браузера используется для первоначального предложения и предупреждения о несовпадении.

`zonedDateTime(instant, timeZone)` в `frontend/src/utils/date.ts` возвращает дату, минуты и HH:MM из одного вызова `Intl.DateTimeFormat.formatToParts`. При повреждённом значении пояса используется UTC. Навигация между календарными датами выполняет арифметику над civil dates, без зависимости от DST или пояса компьютера. Старые неиспользуемые helpers браузерной даты удалены.

`useNowMinutes` сохраняет один таймер с периодом 60 секунд и продолжает следить за датой вне today. Завтрашний день может стать сегодняшним без перехода между страницами. Возврат видимости вкладки сразу обновляет часы. Дата и минуты берутся из одного sample. Отдельные таймеры подписей NowLine/NowLine4a удалены; подписи получают HH:MM от общего sampler.

CalDAV и Google Calendar строят обе границы местного дня независимо, затем переводят их в UTC. День перехода DST может занимать 23 или 25 часов. Floating calendar times получают сохранённый пояс; Google `dateTime` без offset использует явно заданный пояс события, если он есть. All-day события сохраняют `start_date` и исключительную `end_date`. Совместимые поля `start`/`end` остаются UTC instants, но не определяют календарную дату all-day события. Ключи календарного кеша содержат namespace v2 и timezone.

Todoist и Habitica получают один снимок сохранённого пояса и местной даты на запрос. Today/overdue scope и cache key используют этот снимок. Frontend больше не отправляет `carry_overdue`, backend игнорирует старый флаг. Прямые вызовы сервиса также разрешают сохранённый пояс владельца аккаунта, если caller не передал `local_today`.

Преобразование event → block и travel padding использует тот же пояс и просматриваемую дату. Пересечение полуночи обрезается по границам выбранного дня; нулевая длительность сохраняет отдельную подсказку диалога.

## Инвентаризация времени

| Путь | Требуемая семантика |
| --- | --- |
| `schedules/window.py`, root/login redirect, schedule views, AI prompt/apply | Сохранённый пояс пользователя. AI fingerprint включает timezone и проверяется под блокировкой перед записью. |
| `calendar_sync/time.py`, CalDAV/Google services | Полный местный календарный день → UTC interval. Timed events сохраняют instant, all-day events сохраняют civil dates. |
| Todoist/Habitica views, services, cache scope | Один `local_today` в сохранённом поясе на запрос. Пояс входит в cache identity. |
| Analytics views и defaults services | Пользовательский местный день и часы. Streak передаёт дату в per-day fallback, чтобы не добавлять запрос настроек на каждый день. |
| `date.ts`, `useNowMinutes`, DateNavigator, SkippedTasks | Один instant → saved-zone date/minutes. Civil date navigation не зависит от DST. |
| Schedule, NowLine/NowLine4a, notifications | Общие clock refs страницы. Существующая защита уведомлений от replay после долгой паузы сохранена. |
| `useFocusIndicatorController`, PiP | Сохранённый пояс передаётся вместе со snapshot расписания и сохраняется при переходе на другую страницу. |
| ExternalEventsPanel, `externalEventPast`, `travelRules`, AddToScheduleDialog | Timed instants форматируются и сравниваются в сохранённом поясе. All-day диапазоны используют date-only поля. |
| Settings и timestamps интеграций | Сохранённый пояс. Определение браузерного пояса остаётся advisory input. |
| Analytics heading и daily export | Серверная civil date выбранного расписания и naive HH:MM блоков. Дополнительная конвертация даты не нужна. |
| Playwright `djangoToday`/seed localdate | Местный день тестового пользователя, чтобы smoke harness не выбирал другой день при отличии server timezone. |
| `updated_at`, account verification, OAuth expiry | Абсолютные instants для версий кеша и срока действия. Они не определяют пользовательский день. |

В пользовательских путях не осталось `localdate()`/`get_current_timezone()` для выбора дня. Browser `getHours`/`getDate` также больше не определяют часы расписания.

## Смена пояса и незавершённые запросы

Frontend external-source composables отменяют предыдущие GET, очищают строки и игнорируют поздние результаты после смены timezone или местного дня. Поздний failure completion не восстанавливает старую задачу даже после последовательности UTC → другой пояс → UTC. Страница перечитывает все внешние источники и закрывает открытый event-to-block dialog.

Владелец revision сбрасывает context generation, AI thread и исторические snapshots. Если старая запись ещё выполняется, новый writer gate остаётся закрытым до её завершения и последующего успешного чтения canonical schedule. GET, начавшийся до завершения старого POST, не может открыть gate. Смена пользователя или даты не переносит этот gate в новый scope.

Backend AI уже захватывал timezone в R04. R06 сохранил эту защиту и проверил её реальными запросами: изменение пояса после построения prompt приводит к `409 schedule_changed`, без применения устаревших действий. Отказ запускает чтение актуального контекста и позволяет продолжить работу.

Существующие блоки остаются на записанных HH:MM при смене timezone. Перенос их абсолютного времени не выполняется.

## Ограничения модели

Блок хранит civil date и naive HH:MM. При возврате DST две разные точки времени могут иметь одинаковое местное `01:30`. R06 не меняет модель хранения: диапазон между двумя такими точками отображается как нулевая длительность, и AddToScheduleDialog требует скорректировать время или travel padding. Обратный по wall clock диапазон отключает подтверждение. Эти случаи закреплены тестами. Для представления обоих повторений часа потребуется отдельное изменение модели.
