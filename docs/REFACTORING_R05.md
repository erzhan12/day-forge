# R05: история Undo и состояние клиента

Страница расписания хранит один подтверждённый снимок: блоки, статус и revision. `useScheduleRevision` принимает начальные данные Inertia, затем обновляет этот снимок из ответа успешной записи. Компоненты, drag-and-drop, AI и Undo читают его через одного владельца состояния.

## Жизненный цикл записи

`begin` разрешает одну запись для текущей даты и пользователя. Он фиксирует блоки до операции, revision и поколение страницы. Пока запись выполняется или её результат сверяется с сервером, следующая запись не стартует.

Полный успешный ответ сразу заменяет снимок. Дополнительный GET для отображения блоков не нужен. Старые props не могут понизить принятую revision. Если нужен GET для других данных страницы, ответ не становится основанием для перепривязки старого Undo к более новой версии.

При конфликте, потере ответа или неполном ответе владелец перечитывает `blocks`, `schedule` и `auth_user_id` вместе. Он ждёт callbacks Inertia и проверяет дату и поколение. Успешная запись с неудавшимся обновлением страницы остаётся успешной записью; интерфейс сообщает о проблеме обновления. POST автоматически не повторяется.

Если результат неизвестен, небезопасная история очищается. Ошибка клиента или прерывание fetch не доказывают, что сервер откатил транзакцию.

## Исторические версии Undo

Каждая запись содержит:

- снимок блоков до принятой операции;
- revision до операции;
- ожидаемую revision после неё;
- дату и описание операции.

История создаётся только из метаданных подтверждённой операции. Текущая revision из последнего GET не заменяет историческую ожидаемую версию. Ask, no-op, отказ и неподтверждённый результат не создают новую запись Undo. Для частично принятой AI-команды используется фактический diff.

Restore отправляет ожидаемую версию записи истории. После успешного Undo его новая revision может стать ожидаемой версией только для непосредственно предшествующей записи непрерывной цепочки. Например, A создаёт revision 1, B создаёт 2, Undo B создаёт 3. Только подтверждённая связь B с A позволяет Undo A ожидать 3 вместо 1.

Конфликт или внешнее изменение разрывают эту цепочку. Повторная отправка старого снимка с новой версией запрещена. Поздний результат другой даты или пользователя не обновляет текущие блоки, сообщения AI и уведомления Undo.

Status-политика restore сохранена: он не превращает восстановление в новое ручное редактирование. Завершение обзора увеличивает revision и отклоняет старый Undo. Первая версия по-прежнему восстанавливает snapshot через замену набора строк. Переход к обратному diff с сохранением идентичности восстановленных блоков требует отдельного протокола и не входит в R05.

## Completion и сессия

Быстрые переключения completion выполняются последовательно. Ошибки 400/403/404/409, сетевые ошибки и неизвестный результат не запускают повтор PATCH. Конфликт или неизвестный результат отменяют уже накопленные намерения; пользователь может повторно выбрать состояние после сверки расписания.

Inertia передаёт `auth_user_id`. Смена пользователя, logout и недействительная сессия очищают состояние владельца, историю и общий AI-контекст. Сохранённые данные индикатора фокуса тоже очищаются при смене владельца.

Запросы изменения расписания передают `X-Schedule-User` из захваченного контекста страницы. Сервер сравнивает его с текущей сессией до выполнения записи. Это закрывает случай, когда пользователь вошёл в другой аккаунт во второй вкладке, а старая вкладка отправила snapshot на ту же дату с совпадающей revision. Несовпадение возвращает `401` с `code: session_invalid`.

Ответ redirect на страницу входа распознаётся HTTP-клиентом как недействительная сессия. Он не считается успешной записью с некорректным JSON. Обычный 403, например отказ CSRF, остаётся отдельной ошибкой.

## Проверки

Итоговые результаты полного прогона и браузерных сценариев записаны в разделе R05 файла `REFACTORING_PLAN.md`. Регрессии покрывают непрерывную цепочку Undo, конкурентную запись другой вкладки, смену даты и пользователя, поздние AI/Undo-ответы, потерю ответа после commit, ошибку reload, быстрые completion, удаление категории и off-grid блоки.
