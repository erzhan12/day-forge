# R08: общая инфраструктура интеграций

Статус на 10 октября 2026 года: реализовано и проверено локально. R00–R07 сохранены. Коммит, push и публикация не выполнялись.

## Backend

`common/integration_crypto.py` содержит общие Fernet-функции. Обёртки провайдеров задают имя настройки и безопасное сообщение ошибки. Сохранены четыре независимых ключа, формат ciphertext и публичные функции существующих модулей. Миграция данных не требуется. Проверены старый ciphertext, `bytes`, `memoryview`, неверный ключ, пустая и некорректная конфигурация, независимость ключей и ciphertext с некорректным UTF-8. Диагностика не содержит расшифрованных данных.

`common/integration_cache.py` собирает одинаковые части versioned keys и обновляет версию аккаунта без сохранения устаревших credentials. Провайдеры сохраняют namespace, TTL и особенности фильтрации. Google key по-прежнему содержит account ID; task keys содержат filter scope; все ключи учитывают timezone из R06. Cache I/O асинхронного Google endpoint выполняется через `sync_to_async`. Отдельный тест проверяет, что чтение и запись идут вне потока event loop.

`common/integration_checks.py` объединяет проверку ключа и предикат неэффективного кеша. Идентификаторы, сообщения и подсказки Django checks остаются у провайдеров. Отсутствие таблиц до первой миграции обрабатывается как прежде.

`common/integration_response.py` добавляет к resource-ответам явные состояния и код ошибки. Существующие поля и HTTP-статусы сохранены.

| Ситуация | `account_state` | `resource_state` |
| --- | --- | --- |
| Успешная загрузка | `connected` | `ready` |
| Аккаунт отсутствует | `disconnected` | `unavailable` |
| Credentials не приняты | `connected` | `credentials_error` |
| Ошибка конфигурации шифрования | `configuration_error` | `unavailable` |
| Ошибка провайдера | `connected` | `provider_error` |
| Timeout | `connected` | `unavailable` |

Google сохраняет `account_errors` и события доступных аккаунтов при частичном сбое. Неудачная проверка credentials при подключении не меняет ранее сохранённый аккаунт.

## Frontend

`useDatedResource` владеет загрузкой по дате и контексту: request sequence, AbortController, loading, background refresh, очистка при смене дня и disposal. Последние успешные данные текущего дня сохраняются при ошибке обновления. Данные другого дня очищаются до запроса. Состояние подключения определяется payload и явной metadata; сетевой сбой или HTTP 503 сами по себе не доказывают наличие или отсутствие аккаунта.

Controller согласует resource-ответы с чтением account status. Поздний status-ответ не перезаписывает более свежее состояние resource или disconnect. Отключение инвалидирует текущую загрузку и завершение задач, поэтому поздний rollback не возвращает строку отключённого источника.

`useCalendar`, `useGoogleCalendar`, `useTodoist` и `useHabitica` содержат URL, decode, сообщения и особенности данных. Google partial success остаётся в его адаптере. Некорректный успешный payload не устанавливает подключение.

`useTaskCompletion` объединяет оптимистическое завершение задач Todoist/Habitica, rollback и защиту от устаревших GET. Дублирующий POST не отправляется. Смена даты или контекста, включая A → B → A, отменяет прежнюю операцию. Завершённая задача не появляется из запоздавшего GET; защита снимается после ответа провайдера, который подтвердил её отсутствие, чтобы повторяющаяся Habitica daily могла появиться снова.

`useIntegrationAccount` объединяет account-composables страницы Settings: чтение, блокировку операций connect/disconnect, отмену, защиту от поздних ответов и unmount. Google сохраняет список аккаунтов и OAuth redirect; остальные адаптеры сохраняют собственные payload и status.

HTTP-клиент различает истёкшую Django-сессию и provider credentials error по явному серверному контракту. Отмена во время чтения response body остаётся `AbortError` и не превращается в сообщение о сетевой ошибке.

В браузере обнаружено дополнительное расхождение: task-composables сохраняли строки при ошибке, но компоненты скрывали список. Todoist/Habitica панели теперь показывают сохранённые задачи рядом с ошибкой и Retry. Для пустой загрузки остаётся только ошибка. Calendar panel уже поддерживал такое отображение; это закреплено тестами.

## Браузер

Обычный локальный backend и встроенный браузер, пользователь `playwright`, desktop 1280×720 и mobile 390×844:

- Ручное создание блока, Cancel/Delete без native confirm, Undo удаления.
- Реальный AI chat добавил `R08 real AI smoke` на 18:40–19:00. Undo восстановил исходное расписание.
- Реальный AI draft на 16 октября создал `Deep work` на 09:00–12:00. Undo вернул пустой день.
- Обзор дня, Mark reviewed и Markdown preview экспорта.
- Logout и повторный вход на mobile; Logout на desktop после возврата обычного backend.

AI audit: записи **305** (`chat`) и **306** (`draft`), обе `success=True`. AI provider не подменялся.

У тестового пользователя не было credentials внешних сервисов. Подключённые интеграции проверены на временном локальном стенде в `/tmp/day-forge-r08`, который подменял только service-вызовы провайдеров. Django views, шифрование, строки аккаунтов, кеш, HTTP-клиент и UI работали обычным путём. Реальный OAuth и доступ к Apple/Google/Todoist/Habitica в этой проверке не использовались.

На стенде проверены подключение CalDAV/Todoist/Habitica через Settings, два Google-аккаунта с partial success, импорт Google event с Undo, завершение задач обоих task providers и refresh после обновления кеша. Ошибки 502 и credentials 401 сохраняют видимые задачи того же дня; при смене дня старые строки исчезают. Остановка сервера даёт реальный сетевой сбой без HTTP-статуса; список остаётся видимым, повторный refresh после запуска сервера убирает ошибку. Отключение всех пяти тестовых аккаунтов через Settings убирает панель источников при возвращении к Schedule.
