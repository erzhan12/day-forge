# 0055 — Design 4a: layout-switching theme (new `dark_4a` design)

## Context

Day Forge themes today are **token-only**: a theme id (`classic`,
`strategic`, `light_premium`) selects a block of CSS custom properties
under `html[data-theme="…"]` in `frontend/src/app.css`. All three share the
**same layout, geometry, and components** — only colors/fonts/radii change.
`PX_PER_MINUTE = 2` is a hard constant in
`frontend/src/utils/scheduleTime.ts`, consumed by `useDrag.ts` and
`Schedule.vue`. The timeline is rendered by `TimeBlock.vue` / `GapSlot.vue`
/ `NowLine.vue`, always the same set. The right rail composes
`ExternalTasksSidebar.vue` → `TodoistTasksPanel.vue` /
`HabiticaTasksSection.vue`, plus `ExternalEventsPanel.vue` for calendar
events. The AI command bar lives in `CommandBar.vue` backed by the
module-singleton `useChat.ts`.

This feature adds **one new selectable design, `dark_4a`** (per Q1 Option
B) that switches **both palette AND layout/geometry/components** — not just
CSS tokens. It extends the theme system so a theme can also carry a
**layout profile**. The three existing designs stay selectable and
unchanged; `dark_4a` **coexists** with them. All new UI reshapes
**existing loaded data only** — no new data model beyond the single theme
enum value, no integration/sync logic, no AI backend changes.

   `TodoistTasksPanel.vue` / `HabiticaTasksSection.vue`;
   `ExternalEventsPanel.vue` for events). Group order Todoist, Habitica,

   **not derivable** from the loaded Todoist data — `TodoistTask` has no
   `completed` field (`frontend/src/types/todoist.ts:6`), `useTodoist` removes

   first load as the denominator and count completions performed **this
   session** (rows the user checked off in the current view) as the numerator,
   OR display a plain "N left" remaining count. The plan must NOT claim a
   persistent done/total derived from provider state. The progress bar fills
   from that same session baseline — never a hardcoded ratio.
   **Polling invariant (P2-F):** the left sidebar is wired into template-coupled
   poll predicates — `tasksBranch` / `calendarsBranch` / `externalCalendarVisible`
   / `externalPollActive` (`Schedule.vue:404–447`) gate `useExternalSourcePoll`.

   must stay intact for `Schedule.test.ts`.
6. **AI result chip** (Q5): a client-side chip summarizing the last
   applied chat turn (applied block titles/times/categories).
   **Data-source correction (P1-A, load-bearing):** `useChat.ts` does **not**
   retain the applied result in any public state. `messages` is
   `ChatMessage[]` whose entries carry only `{role, content, ask, explanation}`
   (`useChat.ts:27–31`); `data.blocks` / `data.applied` are **locals inside

   public return (`:265`) exposes `messages` / `isProcessing` / `lastError` /

## Theme-system extension: how `dark_4a` registers and selects layout

- **Registration (Option B extends the token system)**: the id
  `dark_4a` is added to (a) backend `UserPreferences.Theme` (persisted
  choice + migration), (b) frontend `ThemeId` union, (c) `KNOWN_THEMES`
  set in `theme.ts`, (d) the `THEMES` registry in `themes.ts` (which drives
  `DesignSelector.vue`'s `v-for` — **no per-id code in the selector**), and
  (e) the `app.css` token block. This is the same five-point wiring the
  existing SYNC ALERT comment describes, now with one more id.
- **Layout selection**: `layoutForTheme(useActiveTheme().value)` yields
  `"4a"` only for `dark_4a`, else `"classic"`. `Schedule.vue` computes a
  reactive `layout` and:
  - branches its timeline template between `Timeline4a.vue` and the
    existing inline `TimeBlock`/`GapSlot`/`NowLine` render;
  - branches the left sidebar between `ExternalRail4a.vue` and
    `ExternalTasksSidebar.vue`, keeping `ExternalEventsPanel.vue` and the
    `tasksBranch` / `calendarsBranch` / `externalCalendarVisible` /
    `externalPollActive` poll predicates (`Schedule.vue:404–447`) consistent
    across both branches (P2-F — see core change #5);
  - branches the command bar chip presentation.
- **Per-design `PX_PER_MINUTE`**: `Schedule.vue` computes
  `pxPerMinute = pxPerMinuteForLayout(layout)` and passes it into
  `itemHeight`, `ghostHeight`, ghost-top math, and into `useDrag`
  (add a `pxPerMinute` accessor param to `useDrag`, defaulting to the
  imported `PX_PER_MINUTE` for backward compatibility with existing tests).
  Per core change #3, `useDrag` must **freeze** `pxPerMinute` (and the 4a
  `timelineOriginMinutes` origin) at `startDrag`, alongside the existing
  `frozenRenderBounds` / `frozenNowMinutes`, so a mid-gesture theme switch
  cannot mix scales. New `useDrag` params are **appended after the existing
  last positional `getWindow`** (`useDrag.ts:263–284`, called at
  `Schedule.vue:147–153`) or moved to an options bag — do not insert them
  before `getWindow` or the window getter is misread as px.

### 4a coordinate model (SINGLE origin — resolves the P1 axis conflict)

The classic renderer uses **compact `renderStart`** compression (the first
item can advance `renderStart` to `firstStart − 30`, `scheduleTime.ts:166`)
and positions the now-line as a **per-slot `%` overlay** (`nowOffsetPercent`,
`spliceNowMarker`). Reusing that model under an absolute
`(t − renderStart) * 1.6` formula is internally inconsistent: a pre-first-block
now marker yields `(now − renderStart) * 1.6 < 0`, and hour ticks, ghost, and
committed drops disagree on today / leading-stub / legacy days.

`dark_4a` therefore uses **one uncompressed absolute axis** with an origin
that is guaranteed to CONTAIN every rendered block, NOT the compact
`renderStart` model. All of the following are load-bearing and must be
implemented together (they resolve the round-2/3 axis findings):

- **Origin name (avoid collision):** call the threaded origin
  `timelineOriginMinutes` — NOT `dayStartMinutes`, which already exists as a
  0053 drop-floor local in `useDrag.ts:344–362` and as `scheduleWindow.startMinutes`
  props (`Schedule.vue:94–99`). Reusing that name would desync the tick/hide
  guards from the drop clamp.
- **Containment (fixes negative/overflow tops for out-of-window legacy blocks,
  `scheduleTime.ts:63–66,177–179`):** classic unions out-of-window blocks into
  its bounds; 4a must do the same. Set
  `timelineOriginMinutes = min(scheduleWindow.startMinutes, earliest block start)`
  and `timelineEndMinutes = max(scheduleWindow.endMinutes, latest block end)`.
  Canvas height = `(timelineEndMinutes − timelineOriginMinutes) * 1.6`. A block
  before the window then has a non-negative top; a block after it still has
  canvas.
- **Uncompressed item build (fixes stub-height holes,
  `scheduleTime.ts:222–233,327–337`):** build the 4a display list by calling
  `buildBaseDisplayItems` with `activeRenderStart = timelineOriginMinutes`,
  `activeRenderEnd = timelineEndMinutes` (i.e. NO compaction), and use
  **`duration_minutes`** for height — NOT `render_minutes` (the compact-stub
  prefix), which would leave holes and shrink the add-here affordance on an
  uncompressed canvas. **Drop `spacer` items** (`scheduleTime.ts:34,341–348`)
  from the 4a list — they only pad flow layout and would paint phantom gaps on
  an absolutely-positioned canvas.
- **Positioning:** every element is `top = (t − timelineOriginMinutes) * 1.6`:
  hour ticks, block tops, gap tops, the now-line, and the drag ghost; the
  committed drop-time inverse is `t = timelineOriginMinutes + top / 1.6`. 4a
  does not accumulate flow heights, so the classic
  `ghostTop = cumulative-preceding-px` invariant (`scheduleTime.test.ts:215`)
  does NOT apply to 4a.
- **Drag map (fixes the P1 drag desync, `useDrag.ts:332–350,369,459`):** the 4a
  drag path must map pointer-Y and ghost through `timelineOriginMinutes`
  (`t = timelineOriginMinutes + localY / pxPerMinute`), NOT through the
  compressed `frozenRenderBounds.renderStart` used by the classic path. Freeze
  `timelineOriginMinutes` + `pxPerMinute` at `startDrag` next to the existing
  `frozenRenderBounds` / `frozenNowMinutes` (`useDrag.ts:447–451`). New params
  are appended **after** the last positional `getWindow` (or an options bag).
- **Single now-line:** 4a builds its base list **without `spliceNowMarker`**
  (`Schedule.vue:689`) and renders one dedicated `NowLine4a` at the absolute
  now-top — no duplicate per-slot marker.
- **Guard:** `now < timelineOriginMinutes` or `now >= timelineEndMinutes` hides
  the now-line rather than positioning it at a negative/overflow top (the
  interval is **end-exclusive**, so `>=` not `>` — otherwise a marker paints at
  the exact lower canvas edge) — explicit test case, alongside early- and
  late-out-of-window block cases.
- **Mid-gesture layout change (P2):** `useDrag` freezes its scale/origin, but
  `Schedule.vue` / `Timeline4a` still render from the LIVE `layout` /
  `pxPerMinute` / origin / `timelineEndMinutes`, so a theme PATCH resolving
