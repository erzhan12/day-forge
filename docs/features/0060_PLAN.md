## 1. RED — author and prove the verifier

Before editing any workflow, save the following as a temporary, untracked verifier and run it with Bash. Keeping it outside the repository preserves the workflow-only diff requirement.

```bash
# Run from the repo root — every path below is repo-root-relative.
set -o pipefail
status=0

# Counts. $(( )) strips the leading whitespace macOS `wc -l` emits, so the
# printed value is bare (e.g. `uses=13`, not `uses=      13`). If rg errors
# (e.g. wrong cwd) wc yields 0, so the `-eq 13` gate below fails closed.
uses_count=$(( $(rg '^[[:space:]]*(-[[:space:]]+)?uses:' .github/workflows | wc -l) ))
# A pinned line = uses: owner/repo@<40-hex>  # <version-comment>. The comment
# accepts v1.2.3, v0.9.0, or a bare floating major v1 (see §2 policy), plus any
# trailing note text. `v[0-9]+(\.[0-9]+)*` rejects malformed `v1.` / `v1..2`.
pinned_count=$(( $(rg '^[[:space:]]*(-[[:space:]]+)?uses:[[:space:]]+[^@[:space:]#]+@[0-9a-f]{40}[[:space:]]+#[[:space:]]+v[0-9]+(\.[0-9]+)*([[:space:]].*)?$' .github/workflows | wc -l) ))

# Total must be EXACTLY 13, and (at GREEN) every one pinned. Hard-coding 13
# stops a deleted/added `uses:` step from passing as e.g. 12==12.
test "$uses_count" -eq 13 || { echo "expected 13 uses entries, found $uses_count" >&2; status=1; }
test "$uses_count" -eq "$pinned_count" || status=1

# Identity guard: the exact multiset of owner/repo (ref + comment stripped) must
# be unchanged — catches a typosquat swap (actions/checkout-evil@<sha>), a
# dropped step, or an added one, none of which the count check alone detects.
# --pcre2 is REQUIRED: rg's default engine rejects the \K (drops the uses:
# prefix); without it the extraction errors to empty and the guard never passes.
actual_actions=$(rg --pcre2 --no-filename -o '^[[:space:]]*(-[[:space:]]+)?uses:[[:space:]]+\K[^@[:space:]]+' .github/workflows | sort)
expected_actions=$(printf '%s\n' \
  actions/checkout actions/checkout actions/checkout actions/checkout actions/checkout \
  actions/setup-node anthropics/claude-code-action anthropics/claude-code-action \
  astral-sh/setup-uv docker/build-push-action docker/login-action \
  docker/setup-buildx-action webfactory/ssh-agent | sort)
[ "$actual_actions" = "$expected_actions" ] || { echo "action identity set changed" >&2; status=1; }

# Repeat consistency: each action pinned more than once (all five actions/checkout,
# both anthropics/claude-code-action) must use ONE identical ref+comment. Capture
# the full pin THROUGH the comment (`#.*$`, not just the version) so a divergent
# trailing note — e.g. `# v1` vs `# v1 (no precise release tag…)` on the same SHA —
# also fails. Group by owner/repo; any owner/repo with >1 distinct pin fails.
# NOTE: at RED (no pins) rg exits 1 → empty $dupe_refs → this gate is a correct
# no-op. Its status is intentionally untested; do NOT add `set -e`/errexit to this
# verifier or the RED run would abort here before printing the red result.
dupe_refs=$(rg --pcre2 --no-filename -o '^[[:space:]]*(-[[:space:]]+)?uses:[[:space:]]+\K\S+@[0-9a-f]{40}[[:space:]]+#.*$' .github/workflows \
  | sort -u | sed -E 's/@.*//' | sort | uniq -d)
[ -z "$dupe_refs" ] || { echo "action pinned to differing SHAs/comments: $dupe_refs" >&2; status=1; }

# No bare movable tag may remain. `rg -n` (not -q) PRINTS the offending lines so
# the RED run surfaces the remaining @v… refs, and exits 0 on match → status=1.
if rg -n '^[[:space:]]*(-[[:space:]]+)?uses:.*@v[0-9]' .github/workflows; then status=1; fi

for file in .github/workflows/*.yml; do
  ruby -ryaml -e 'YAML.parse_file(ARGV.fetch(0))' "$file" || status=1
done

# Diff scope. Compare against HEAD (not the unstaged working tree) so staging a
# stray file between GREEN edits and this run cannot hide it. --summary catches
# create/delete/rename/mode changes the +/- awk filter below does not see.
test -z "$(git diff HEAD --name-only -- . ':(exclude).github/workflows/**')" || status=1
test -z "$(git diff HEAD --summary -- .github/workflows)" || status=1
git diff HEAD --unified=0 -- .github/workflows |
  awk '/^(---|\+\+\+|@@)/ { next }
       /^[+-]/ && $0 !~ /^[+-][[:space:]]*(-[[:space:]]+)?uses:[[:space:]]/ {
         print > "/dev/stderr"; bad=1
       }
       END { exit bad }' || status=1

printf 'uses=%s pinned=%s status=%s\n' "$uses_count" "$pinned_count" "$status"
exit "$status"
```

Run it before resolving or applying pins. It must exit non-zero with `uses=13 pinned=0` and report the remaining `@v…` references, while the action-identity guard, YAML parsing, and the initially empty diff checks pass. Do not proceed unless this red result is observed. The identity multiset and the hard-coded `13` are the security-load-bearing assertions — the point of pinning is defeated if the verifier greenlights a swapped or dropped action, so never weaken them to a bare count.

## 2. Resolve fresh immutable refs

After the red run, resolve each of the eight distinct actions once, prioritizing `anthropics/*`, `webfactory/*`, and `astral-sh/*`, followed by `actions/*` and `docker/*`.

For every action, run at implementation time under `set -o pipefail` so a
failed/rate-limited `gh` call cannot be masked by a downstream `sort`/`tail`
that still exits 0:

```bash
set -o pipefail
sha=$(gh api "repos/<owner>/<repo>/commits/<tag>" --jq .sha)
# Abort unless the resolve succeeded AND returned a real 40-hex SHA (an auth or
# rate-limit failure yields empty/"null" here and must NOT flow downstream).
[[ "$sha" =~ ^[0-9a-f]{40}$ ]] || { echo "resolve failed for <owner>/<repo>@<tag>: '$sha'" >&2; exit 1; }

# Precise version for the comment. Fetch the peeling tags FIRST, gating the API
# call on its own — otherwise a failed/rate-limited `gh api` yields an empty list
# that is indistinguishable from "genuinely no precise tag" and would wrongly
# trigger the floating-major fallback below on a repo that DOES have a release.
peeled=$(gh api "repos/<owner>/<repo>/tags" --paginate \
           --jq ".[] | select(.commit.sha==\"$sha\") | .name") \
  || { echo "tags lookup failed for <owner>/<repo> @ $sha" >&2; exit 1; }
# Among the peeled tags, keep only strict three-part semver of the SAME major as
# the floating tag (no prereleases, no cross-major aliases), then take the
# highest. Filtering BEFORE sort means a v1.3.0-rc.1 can never be selected. An
# empty $ver here is now a TRUE "no precise tag" signal → §fallback policy.
ver=$(printf '%s\n' "$peeled" | grep -E '^v<MAJOR>\.[0-9]+\.[0-9]+$' | sort -V | tail -1)
```

For each result:

- Require the commit value to match exactly `^[0-9a-f]{40}$` (already gated above); never pin an empty/`null` resolve.
- Prefer a precise same-major `vX.Y.Z` comment (`$ver`). **Floating-major fallback policy:** if — and only if — no strict `vX.Y.Z` tag peels to `$sha` (can happen for a floating major like `anthropics/claude-code-action@v1` immediately after an upstream push), still pin the immutable `$sha` and set the comment to the floating major with an explicit note, e.g. `# v1 (no precise release tag at this SHA)`. The §1 pinned-line regex accepts this bare-major form, so GREEN stays reachable; do not block on it and do not guess a version that does not point at `$sha`.
- Record the eight SHA/version pairs in temporary notes only.
- Reuse the identical resolved pair for every repeated occurrence, especially all five `actions/checkout` lines and both `anthropics/claude-code-action` lines.
