# 0105 — Sources rail redesign and collapsible sections

Redesign the Dark 4a left rail ("Today’s sources": Todoist, Habitica, external calendars) to follow the approved mockups, and unify task checkboxes across the app. The user's requests, verbatim:

- «предложи дизайн этих секций, чтобы выглядело красивее»
- «добавить возможность сворачивать секции, но чтобы видно было титул и прогресс бар»
- «рамочка если секция свернута - ок, но если развернута кажется она лишняя» (the frame around the section title)
- «чекбоксы разные, тут круглые, а на блоках основных квадратные остались»

Decisions from clarifying questions:

- Calendar stripe colour is derived on the client from `calendar_name`. No API change.
- A completed task row plays a short leave animation (strike-through and fade, about 250 ms). Completion logic is unchanged.
- The unified rounded-square checkbox applies in **all themes**, to block and task-completion checkboxes.

The rail mounts only when `layout === '4a'`, which `layoutForTheme` (`frontend/src/utils/layoutProfile.ts:5`) returns only for `dark_4a`. Its hardcoded hex values equal the `dark_4a` tokens. Moving to tokens follows RULES.md (theme tokens instead of fixed colours); it is not a light-theme bug fix.

## Target design

**Rail header.** The title is “Today” when `activeDate === todayDate`; otherwise it is the weekday and date (for example “Thu, 19 Nov”). The subtitle shows the formatted active date. Both are formatted from the civil date string through a new `formatShortCivilDate` in `frontend/src/utils/date.ts`, built on the private `utcCivilDate` (`:50`) and formatted with `timeZone: "UTC"` like `formatCivilDate` (`:68–70`). Without that option, noon UTC shows the next weekday at UTC+12 and east. Never use `new Date("YYYY-MM-DD")`, whose UTC midnight shifts the weekday west of UTC. Refresh and collapse stay as icon buttons with existing `aria-label`s and lose their borders.

**Section header.** The whole row is one `<button>` with `aria-expanded` and `aria-controls`. It holds, in order:

- a chevron, rotated −90° when collapsed;
- a provider marker: a coloured dot for tasks, a calendar glyph for calendars;
- the title: “Todoist”, “Habitica”, “Calendars”;
- a right-aligned tabular counter.

**Progress bar.** It sits under the task-section headers, is 3 px high and uses the provider colour. The track is `color-mix(in oklab, var(--border-strong) 80%, transparent)` instead of the current non-token `#2a2d31` (`ExternalRail4a.vue:154`). It is **always visible, including at 0 %, in both states**. Calendars have no bar.

**Collapsed section.** Collapsed, a section is a card: inset 8 px margin, `--border-strong` 0.5–1 px border, 10 px radius and a slightly elevated background (`--bg-elevated`). It shows only the header and bar, or the calendar peek line. **Expanded sections have no frame and no fill.** Adjacent expanded sections are separated by one `--border` hairline. Mouse clicks leave no focus ring; `:focus-visible` shows a `--focus-ring` box-shadow for keyboard users.

**Layout.** Sections take their content height (`flex: 0 0 auto`); `.rail-content` scrolls as a whole. Drop `max-height: 50%` on the calendar section. Order stays Todoist, Habitica, Calendars (calendar last).

**Calendar rows (rail only).** A grid of three columns:

- start time (`HH:MM`, or “All day”);
- a 3 px stripe in the calendar's derived colour;
- the title on the first line; the second line is the source and, for timed events, the duration.

The source is `account_label || calendar_name`, the same fallback as `ExternalEventsPanel.vue:139–141`, because Apple rows carry an empty `account_label`. All-day events show no duration.

Past events keep the existing faded style. “+ Add to schedule” is kept. The duplicate inner “External Calendars” header is removed in the rail only.

**Colours.**

- New tokens `--provider-todoist` and `--provider-habitica`, defined in `:root` and overridden per theme in `frontend/src/app.css` (`classic`, `strategic`, `light_premium`, `dark_4a`), each tuned for contrast on its theme.
- New token `--checkbox-border`, defined per theme.
- The calendar palette is a fixed list of 6–8 hues defined as tokens `--calendar-hue-1…n`, per theme.

## Counter and progress algorithm

`progress()` in `frontend/src/components/ExternalRail4a.vue:110` keeps its baseline/remaining-set semantics (all `captureBaseline` and reset logic stays untouched). Only its output changes. As today, `progress()` returns the rendered text itself, so it is the symbol that enforces the label. It returns `{ label, ariaLabel, percent }`:

1. If `baselineIds === null`, the label is an en dash `–`, `ariaLabel` is “Not loaded yet” and `percent` is 0.
2. Otherwise, `done` is the number of baseline ids absent from the remaining set and `total = baseline.size`. The label is `${done} / ${total}`; `ariaLabel` is `${done} of ${total} completed this session`; percent is `done / total × 100`, or 0 when `total` is 0.

Calendar counter and peek line come from one computed, `calendarSummary` in `ExternalRail4a.vue`, which returns `{ counter, peek }`. It uses `events`, `eventsLoading`, `eventErrors`, `accountErrors`, `activeDate` (passed as the viewed date), `todayDate`, `timeZone` and `nowMinutes` with `isExternalEventPast` (`frontend/src/utils/externalEventPast.ts:14`). Rules 1–3 are exclusive; the first match wins. Rule 4 is applied afterwards as a post-processing step on rule 3’s result:

1. `events.length === 0 && eventsLoading`: counter `–`, peek `Loading…`.
2. `events.length === 0` with any `eventErrors` or `accountErrors`: counter `–`, peek `Calendars unavailable`. This mirrors the panel, which shows its empty message only when there are no banners and no account errors (`ExternalEventsPanel.vue:164–169`).
3. Otherwise `upcoming` is the list of events not past, and the counter reads `${upcoming.length} upcoming`. The peek takes the first timed event in `upcoming`, in the merged list's existing order (start, title, `external_uid`; `useExternalSources.ts:113–119`; no re-sort). It reads `Now · Title` only when `activeDate === todayDate` and the event has started: its zoned start (`zonedDateTime(new Date(ev.start), timeZone)`) folded to minutes relative to today with `civilDayDelta(today, start.date) * 1440 + start.minutes` is `<= nowMinutes`; with `nowMinutes === null` it is never `Now`, mirroring `externalEventPast.ts:24`. This is the same folding `isExternalEventPast` uses for the end (`externalEventPast.ts:23–27`), so an overnight event that began yesterday at 23:00 reads `Now`. Otherwise it reads `Next · HH:MM Title`. With no timed upcoming event but at least one upcoming all-day event it reads `All day · Title`. Otherwise it reads `Nothing upcoming`.
4. Post-processing: when events exist but there is any `eventErrors` entry (a provider-wide failure, for example a Google banner beside Apple rows, as in `ExternalEventsPanel.test.ts:103`, or a banner beside the same provider’s retained rows, `:119`) or any `accountErrors` entry, the counter keeps rule 3. The peek gets the suffix ` · N unavailable`, where N = `eventErrors.length` plus `accountErrors.length` only when there is no Google banner. Google's all-account failure produces both a banner and account errors for one outage (`useGoogleCalendar.ts:29–37`), and counting both would show “2 unavailable”. When there is no such failure but `eventsLoading` is true with events present, the peek gets ` · Loading…`; a failure suffix takes precedence over the loading one, because a same-date reload keeps rows while the slower provider is still loading (`useDatedResource.ts:120–130`, `useExternalSources.ts:122`). and the section's `hasError` is true.

The peek line renders only while the section is collapsed.

**Collapsed sections with loading or errors.** Counter and bar stay live while their panel loads or errors, and an error does not auto-expand the section. The error banner lives inside the hidden body, so a collapsed task section with an error shows a peek line in the danger text colour with the panel's own error message (`state.error`, ellipsised to one line), followed by “· Expand”. The message is not a fixed “Couldn't load” text, because a failed completion also writes `state.error` and re-inserts the row (`useTaskCompletion.ts:75–84`). The peek must not claim a load failure in that case. This peek has `role="status"` and uses the existing danger text token. It is also referenced by `aria-describedby` on the header button, so the error is conveyed by text, not colour alone. A collapsed calendar section uses rule 2 or 4 above in the same way.

A collapsed task section that is loading with no baseline yet (`baselineIds === null`: first load or date change) shows the peek `Loading…` in an `aria-live="polite"` region, because the panel's own live nodes are inert while collapsed. Silent background refreshes do not set `loading` (`useDatedResource.ts:130`), and the counter deliberately freezes during an in-flight load (`externalRail4a.test.ts:203`), so no other loading cue is added.

Calendar colour derivation is a new pure util. It computes a deterministic 32-bit string hash (FNV-1a) of `calendar_name`, coerced to unsigned with `>>> 0`, takes it modulo the palette length, and returns the CSS variable name. An empty name maps to index 0.

## Collapse persistence

New `frontend/src/utils/externalRailSectionsStorage.ts`, following `externalTasksSidebarStorage.ts`:

- key `day-forge:external-rail:collapsed`, matching the existing `day-forge:…` storage keys;
- value is a JSON object `{ todoist?: boolean, habitica?: boolean, calendars?: boolean }`;
- `readExternalRailCollapsed()` validates the shape, always returns a complete `{ todoist, habitica, calendars }` object of booleans. Missing, corrupt or non-boolean entries become `false` (expanded), so the default lives in this function, and catches storage exceptions;
- `writeExternalRailCollapsed(value)` catches quota and security errors.

Default is expanded. The rail reads the value once at setup and writes on each toggle.

## Unified checkbox (all themes)

There is one global style in `frontend/src/app.css`, class `.df-checkbox`, on a native `<input type="checkbox">`. Native input semantics, the `change` event and keyboard behaviour stay as they are.

- `appearance: none`, 16 × 16 px, 4 px radius, 1.5 px `--checkbox-border` border.
- Hover border and checked fill use `var(--checkbox-color, var(--accent))`. The checked state paints the fill with `background-color` and the tick with `background-image`, an SVG data URI. It does not use `::after`, which a replaced `<input>` does not reliably render, or `mask-image`, which would mask the fill and border too. The tick comes from two global tokens holding the same SVG path with its colour baked in, `--checkbox-tick-light` (white) and `--checkbox-tick-dark` (near-black). `--checkbox-tick` selects one:
  - The default is `var(--checkbox-tick-light)`. Themes whose `--accent-contrast` is dark (`strategic`, `dark_4a`) default to `--checkbox-tick-dark` for accent fills.
  - `TimeBlock.vue` sets `--checkbox-tick` per block from a small luminance helper, `tickVariantFor(hex)` in `frontend/src/utils/categoryColors.ts`, because category hexes vary.
  - The provider tokens set their tick variant next to `--provider-*`.
- `:disabled` renders at reduced opacity with `cursor: not-allowed`. The existing `.saving` (opacity 0.5, `cursor: progress`) is kept.
- `:focus-visible` shows the `--focus-ring` box-shadow.

## OpenSpec

Change `openspec/changes/0105-sources-rail-redesign/`, created after this plan is approved and the feature branch exists (README step 2). The proposal links here. The capability is `frontend/external-sources`; deltas are `## ADDED Requirements` only, because no current requirement covers the rail:

1. **Rail section collapse persistence.** Toggling a rail section header SHALL flip that section's collapsed state, and each section's state SHALL be restored per section across reloads, defaulting to expanded.
   - Enforced: `frontend/src/components/ExternalRail4a.vue::toggleSection`, `frontend/src/utils/externalRailSectionsStorage.ts::readExternalRailCollapsed`, `frontend/src/utils/externalRailSectionsStorage.ts::writeExternalRailCollapsed`.
   - Tests: the new rail toggle and restore tests, and the storage tests.
2. **Rail session progress label.** The counter SHALL read `done / total` from the session baseline, `–` before a baseline exists, without changing baseline capture.
   - Enforced: `frontend/src/components/ExternalRail4a.vue::progress`.
   - Tests: the updated baseline tests.
3. **Rail calendar summary.** The calendar counter SHALL count events not yet past, and the collapsed peek SHALL name the next timed event, or an all-day event, or say nothing is upcoming. It SHALL report loading or unavailable instead of an empty result while the list is loading or failed.
   - Enforced: `frontend/src/components/ExternalRail4a.vue::calendarSummary`.
   - Tests: the new peek tests.

The checkbox look, tokens, colour derivation and animation are presentation only, so they get no requirements. The `inert` body, the title, counter and bar staying visible while collapsed, and the collapsed error text all live in `RailSection`/rail templates with no owning symbol. They are covered by Vitest and listed as a spec gap in the review notes, not written as requirements with a false `Enforced:` anchor. Keep each requirement body under 500 characters, with `Tests:` under the scenarios. The `Tests:` lines above name test groups; the change cites exact `path::describe::title` anchors once the Vitest titles exist (`backend/scripts/check_spec_anchors.py` resolves them).
