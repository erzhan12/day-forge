# 0113 — Mobile schedule (Dark 4a, max-width 640 px)

Status: in progress. Source: the design mentor's SPEC section 11 «Mobile» and the two agreed mockups (rest, chat focused). Issues: #333 (edit block time and category in the mobile sheet) is out of scope here.

## Goal

At 640 px and below, the Dark 4a Schedule page becomes a single-column phone layout: one-line 56 px header, a fixed-row list (block 52 px, free row 48 px, no time axis), a FAB, bottom sheets for add and edit, an Undo toast, and a collapsed AI chat bar that expands on focus. Wider screens and the other themes do not change.

## Decisions (owner, 2026-11-28)

1. Deleting a block on mobile has no confirmation dialog; it shows `Block deleted · Undo` for 5 seconds. `.claude/rules/ui.md` records the exception.
2. In rest state the full chat privacy text sits behind ⓘ. The hint is moved, not removed; `ai-safety.md` and `ai-chat-privacy-hint-always-on.mjs` follow.
3. Touch drag is deferred (stage 7); mobile ships without drag.
4. The edit sheet edits the title only. Time and category are issue #333.
5. `Today`, the draft badge, `Regenerate draft` and the time-zone banner are not shown on mobile.
6. Other themes at 640 px and below keep their current layout.
7. Implemented without Claude Code or Codex: small PRs, self-review plus the GitHub claude-review check.

## Current code that stays

`useViewport` (`isWide`, 1024 px) keeps unmounting the rails and mounting the dock below 1024 px. The mobile flag is `layout === '4a' && isMobile`, where `useIsMobile` reads `(max-width: 640px)`. Mobile components are new files; `TimeBlock.vue` and `CommandBar.vue` are not branched where avoidable. Completion, delete and create keep going through `useBlockCompletion`, `useSchedule` and `registerMutationUndo`.

## Stage 1 notes

- `base.html` meta applies to every page and theme. Because `viewport-fit=cover` lets content draw under the notch, `app.css` pads `body` with `env(safe-area-inset-*)` (0 on desktop), which keeps the pre-change look; the mobile header and chat panel take the top and bottom insets over in stages 2 and 6.
- `interactive-widget=resizes-content` only changes behavior in Chrome on Android 108+ (the layout viewport shrinks with the keyboard). iOS Safari ignores it; stage 6 adds `visualViewport` handling.
- Mobile-only CSS sits in `html[data-theme="dark_4a"]` inside `@media (max-width: 640px)`; `-webkit-text-size-adjust` is under `dark_4a` only.
- The fixed dock below 1024 px gets `padding-bottom: 8px + --safe-bottom` so the home indicator does not cover the field until stage 6 replaces it.
- `html` and `body` already resolve to `#17181a` in Dark 4a (`--bg-page`); the mobile block restates it so the overscroll layer cannot differ.

## Open points

- Criterion «8 rows without scroll at 375×667» does not fit the pixel budget (about 7 rows); confirm with the designer in stage 3.
- `Calendars` in the ⚙ menu needs external-source polling while the sheet is open (`useExternalSources` currently keys on `isWide`); decide in stage 2.
- Chat thread, errors, clarifications and recovery buttons are not specified for mobile; decide in stage 6.
