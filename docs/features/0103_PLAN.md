# 0103 — Hardening: `create_block` 500s on malformed JSON field types

## Context

`POST /api/schedules/<date>/blocks/` is handled by `create_block` in
`backend/schedules/api.py` (function at line 47). It parses the JSON body but
does **not** validate that fields are the expected types before calling
`.strip()` or performing set-membership. Malformed payloads from any
authenticated user crash the view with uncaught exceptions (HTTP 500 +
traceback) instead of structured 400s.

The sibling endpoint `create_block_from_event` in the **same file** (function
at line 127, feature 0026) **already** has the exact defensive checks that
`create_block` is missing, and even carries a code comment documenting the
hole. It is the **reference implementation to mirror**. This is a hardening
bugfix, **not a refactor**: we mirror the sibling's validation inline; we do
**not** extract shared validation into a helper (explicitly out of scope per
issue #103).

### Verified crash sites in `create_block` (current code)

| Line | Code | Behavior on malformed input |
| --- | --- | --- |
| 54 | `data = json.loads(request.body)` | No `isinstance(data, dict)` check. |
| 60–64 | `for field in ("start_time","end_time"): if field not in data: return 400` | A non-object body (e.g. a JSON list) still passes `field not in data`, returning a **misleading** `"start_time is required"` 400 — not a crash, but wrong. |
| 66 | `_validate_block_times(data["start_time"], data["end_time"])` | Non-string times already soft-fail to a 400 `"Invalid time format"` inside the helper. |
| 70 | `title = data.get("title", "").strip()` | **CRASH:** `AttributeError: 'int' object has no attribute 'strip'` → HTTP 500 when `title` is a non-string (e.g. `123`). |
| 80–81 | `category = data.get("category", "other"); if category not in VALID_CATEGORIES` (a `set`) | **CRASH:** `TypeError: unhashable type: 'list'` → HTTP 500 when `category` is a list/dict. |
| — | (missing) | `create_block` does **not** call `_reject_oversized_body(request)`, unlike its siblings at lines 142, 449, 655. |

Reproduced 500s (direct view call):
- `{"start_time":"09:00","end_time":"10:00","title":123}` → `AttributeError` → 500
- `{"start_time":"10:00","end_time":"11:00","title":"x","category":[]}` → `TypeError` → 500

## Reference implementation (mirror these exact lines)

`create_block_from_event` in `backend/schedules/api.py`:

- **Line 142–144** — oversized-body guard idiom (the helper returns a response
  object **or** `None`; return it when not `None`):
  ```
  oversized = _reject_oversized_body(request)
  if oversized is not None:
      return oversized
  ```
- **Line 151–155** — non-object body rejection with the canonical error shape
  `{"errors": {"<field>": "<msg>"}}`:
  ```
  if not isinstance(data, dict):
      return JsonResponse(
          {"errors": {"body": "Request body must be a JSON object."}},
          status=400,
      )
  ```
- **Line 157–172** — the `isinstance(..., str)` checks (with the documenting
  comment) for `start_time`/`end_time` (inside the required-field loop) and for
  optional `title` / `category` when present.

Supporting facts:
- `_reject_oversized_body = reject_oversized_body` alias is defined at
  `backend/schedules/api.py:34`; the impl lives at
  `backend/schedules/http.py:31` (returns a 413 `JsonResponse` or `None`).
- `VALID_CATEGORIES` is imported at `backend/schedules/api.py:13` (defined at
  `backend/schedules/http.py:21` as a `set`).
- Canonical error response shape everywhere: `JsonResponse({"errors": {...}}, status=...)`.

## Changes

### File: `backend/schedules/api.py` — `create_block` (line 47)

Insert the following, mirroring `create_block_from_event`, **without altering
any existing business validation** (required title, `len <= 255`, category
enum, overlap check, row locking, `full_clean`, `mark_active_on_edit`):

1. **Oversized-body guard** — after the `parsed_date` block and **before**
   `json.loads` (currently line ~52), add the `_reject_oversized_body(request)`
   call using the exact line 142–144 idiom (returns 413 when oversized, else
   `None`). This matches where the sibling places it relative to `json.loads`.

2. **Non-object body rejection** — immediately after the successful
   `json.loads` / `JSONDecodeError` block (currently line ~56, before
   `get_or_create` at line 58), add the `isinstance(data, dict)` check
   returning 400 with message `"Request body must be a JSON object."` (mirror
   line 151–155).

   > Note: acceptance criterion phrases this as `"body must be a JSON object"`;
   > the sibling's established, exact message is `"Request body must be a JSON
   > object."`. **Use the sibling's wording verbatim** so the two endpoints stay
   > in sync (the criterion is satisfied by the substring "JSON object"). The
   > tests below assert on this exact string.

3. **String-type checks for `start_time` / `end_time`** — inside the existing
   `for field in ("start_time","end_time")` loop (line 60–64), after the
   `field not in data` check, add the `isinstance(data[field], str)` guard
   returning 400 `"{field} must be a string."` (mirror line 160–172). Keep the
   existing `_validate_block_times(...)` call at line 66 unchanged — it stays as
   the parse/granularity/range validator for well-typed string inputs.

4. **String-type checks for optional `title` / `category`** — before the
   `title = data.get("title","").strip()` line (line 70), add:
   - `if "title" in data and not isinstance(data["title"], str):` → 400
     `"Title must be a string."`
   - `if "category" in data and not isinstance(data["category"], str):` → 400
     `"Category must be a string."`

   These guards eliminate the two reproduced 500s (the `.strip()` AttributeError
   and the unhashable-`category` TypeError) **before** the crashing lines run.

**Explicitly unchanged / out of scope:** the 5-minute granularity rule
(`create_block` keeps `_validate_block_times`; do not swap to the sibling's
off-grid `_parse_time_or_error` path), the category enum, the overlap/locking
transaction, `full_clean`, and `mark_active_on_edit`. Do **not** extract shared
validation into a helper.
