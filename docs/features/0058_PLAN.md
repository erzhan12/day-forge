# 0058 — Inject focus-indicator view CSS into the Document PiP window

Frontend-only bugfix for feature 0049 (GitHub #131). No backend, no
migrations, no API, no `dark_4a` work.

> **For agentic workers:** after this plan is approved, create

**Goal:** The always-on-top focus indicator must show a visible progress
track + fill + styled Complete control inside Chrome's Document
Picture-in-Picture window.

**Architecture:** Keep the 0049 design: a second `createApp` mounted into a
**foreign** `Document`, with a dedicated `<style>` injected into that
document. Expand that injected stylesheet so it contains the *view* rules
(`.focus-indicator`, `.fi-bar`, `.fi-fill`, `.fi-complete`, …), not only
html/body chrome. Do **not** clone `app.css`. Vue `<style scoped>` on
`FocusIndicatorView.vue` cannot reach the PiP document (Vite injects it
into the opener page only).

**Tech stack:** Vue 3, Vite, Vitest, Document Picture-in-Picture
(`window.documentPictureInPicture.requestWindow`).

**Spec:** this file + `docs/features/0049_PLAN.md` Slice 3 (own PiP
stylesheet, do not clone the app stylesheet) and Slice 4 (generic bar +
icon-only Complete; no block-identifying text).

## Global constraints

- Privacy invariant unchanged: PiP DOM, `document.title`, and injected CSS
  contain no block title, category, date, times, or remaining-minutes copy.
- Do **not** copy `document.styleSheets` / `app.css` into the PiP (0049
  forbade this; a production CSS chunk can also carry unrelated selectors).
- Do **not** change progress math, active-block selection, Complete
  mutation semantics, window size (`240×60`), or the Show-indicator control.
- One source of truth for PiP visuals: the string injected as
  `style.textContent` in `useFocusIndicator`. Delete the now-dead
  `<style scoped>` block on `FocusIndicatorView.vue` so the two cannot
  drift.
- jsdom does not reliably apply author styles via `getComputedStyle`.
  Tests assert the **injected stylesheet text** and the **mounted DOM**,
  not computed pixels.

## Why it is blank today (verified)

`useFocusIndicator.ts` opens the PiP, writes this into `win.document.head`,
then mounts `FocusIndicatorView`:

```css
:root { color-scheme: light dark; }
html, body { margin: 0; height: 100%; }
body { display: flex; align-items: center; }
```

`FocusIndicatorView.vue` holds the real layout in `<style scoped>`
(`.fi-bar { height: 12px; flex: 1; … }`, `.fi-fill { background: currentColor }`,
`.fi-complete { background: transparent; border: 1px solid currentColor }`).
Vite injects that CSS into the **opener** document. The PiP is a different
`Document`, so those rules never apply.

Observed symptom: native grey ✓ button (unstyled `<button>`), empty dark
canvas, no track. Data path is fine (`active === true`; timeline remaining
time matches). Not a 0055/`dark_4a` regression — these two files are
untouched there.

Existing tests never inspect PiP `<style>` text, so they stay green.

## Injected stylesheet (copy verbatim into `PIP_STYLES`)

Keep the existing html/body chrome, then append the current SFC rules
**without** Vue `data-v-*` selectors (unscoped `.fi-bar` still matches
elements that Vue tagged with a scope id):

```css
:root { color-scheme: light dark; }
html, body { margin: 0; height: 100%; }
body { display: flex; align-items: center; color: CanvasText; background: Canvas; }
.focus-indicator {
  display: flex;
  align-items: center;
  gap: 8px;
  width: 100%;
  box-sizing: border-box;
  padding: 0 12px;
  font-family: system-ui, sans-serif;
}
.fi-bar {
  flex: 1;
  height: 12px;
  border-radius: 6px;
  background: rgba(128, 128, 128, 0.3);
  overflow: hidden;
}
.fi-fill {
  height: 100%;
  background: currentColor;
  transition: width 0.25s ease;
}
.focus-indicator[data-state="error"] {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}
.fi-complete {
  flex: none;
  min-width: 28px;
  min-height: 24px;
  border: 1px solid currentColor;
  border-radius: 4px;
  background: transparent;
  color: inherit;
  cursor: pointer;
  font-size: 14px;
  line-height: 1;
}
.fi-complete:disabled {
  opacity: 0.5;
  cursor: default;
}
.fi-complete:focus-visible {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}
.fi-retry {
  flex: none;
  font-size: 11px;
  text-transform: uppercase;
  letter-spacing: 0.04em;
}
.fi-neutral {
  flex: 1;
  text-align: center;
  opacity: 0.6;
}
.fi-sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
@media (prefers-reduced-motion: reduce) {
  .fi-fill { transition: none; }
}
```

`color: CanvasText` / `background: Canvas` make `currentColor` follow
`color-scheme: light dark` so the fill is visible on a dark PiP canvas.
Do not introduce category tokens (`oklch` category hues, `--cat-*`).

If the SFC class names in HEAD differ from `.fi-bar` / `.fi-fill` /
`.fi-complete` / `.fi-retry` / `.fi-neutral` / `.fi-sr-only` /
`.focus-indicator`, use the names that are actually in
`FocusIndicatorView.vue` — the test below must match those names.

- [ ] **Step 1: Write the failing test**

Add to the `useFocusIndicator` describe (reuse the existing fake PiP;
do not build a new fake). Use `FocusIndicatorView` so the mounted DOM
also contains `.fi-bar` (import from
`../src/components/FocusIndicatorView.vue`):

```ts
it("injects the view layout stylesheet into the PiP document (not only html/body chrome)", async () => {
  const win = makeFakeWindow()
  installFakePip(win)
  const fi = useFocusIndicator({
    component: FocusIndicatorView,
    props: () => ({
      active: true,
      progressPercent: 83,
      completing: false,
      errorState: false,
      disabled: false,
    }),
  })
  await fi.open()
  await flushPromises()

  const css = [...win.document.querySelectorAll("style")]
    .map((el) => el.textContent ?? "")
    .join("\n")

  expect(css).toMatch(/\.fi-bar/)
  expect(css).toMatch(/height:\s*12px/)
  expect(css).toMatch(/\.fi-fill/)
  expect(css).toMatch(/\.fi-complete/)
  expect(css).toMatch(/background:\s*transparent/)
  // Privacy / 0049: must not dump the app stylesheet.
  expect(css).not.toMatch(/\.time-block/)
  expect(css).not.toMatch(/Standup with Bob/)

  expect(win.document.querySelector(".fi-bar")).not.toBeNull()
  expect(win.document.querySelector(".fi-fill")?.getAttribute("style")).toContain(
    "83%",
  )
  fi.cleanup()
})
```

Prop names must match `FocusIndicatorView.vue` (`active`,
`progressPercent`, `completing`, `errorState`, `disabled`) and the
config field names already used in this test file (`component`,
`props`).
