# 0044 — Remove the orphan `/command/` AI endpoint and the `useAI` composable

## Context

Feature 0007 rerouted the `CommandBar` UI to the multi-turn `/chat/` endpoint; the one-shot
`POST /api/ai/schedules/<date>/command/` endpoint and the frontend `useAI` composable have had
**zero production callers** since. Feature 0040 migrated the feature-0009 async-boundary
regression coverage (`sync_to_async` rollback propagation) that historically lived only in the
`/command/` integration suite. With that coverage relocated we can now delete the dead surface
end-to-end: backend view + route + rate-limit decorator + `run_command` service fn + the
command-only prompts, plus the frontend composable, Playwright scripts, Makefile target, and docs.

This is a **cross-boundary removal that changes a public API surface**. The load-bearing risk is
**test coverage loss**: `backend/tests/test_ai_views.py` exercises the *shared* apply path
(`_apply_actions_sync`, `mutation_planner`, row-locking, granularity, day-window, midnight-wrap,
interaction truncation, parse-error logging) *through* `/command/`. Any such behavior not already
duplicated by the chat suite MUST be migrated **before** the endpoint is deleted so coverage never
drops.
