# 0049 — Focus indicator: always-on-top progress for the current block

GitHub issue #131. Frontend-only (Vue 3 / TypeScript / Inertia). No backend,
no migrations, no new polling, no new interval.

## Context

Add a privacy-preserving **Document Picture-in-Picture (PiP)** focus
indicator for the installed Day Forge Chrome App on macOS. A small
always-on-top PiP window shows **only** a horizontal progress bar of the
current unfinished block plus an icon-only Complete (✓) control — no block
title, category, date, times, or remaining-minutes text (the privacy
invariant). The user clicks a persistent **Show indicator** header control
once per app-window launch (Chrome requires transient user activation for
`documentPictureInPicture.requestWindow()`). The window then auto-follows all
subsequent blocks (active ↔ neutral) without reopening, stays open in a
neutral state between blocks, and must not outlive the main app window.

The Complete control **must reuse the exact same mutation semantics** as the
timeline checkbox in `TimeBlock.vue` (concurrency guard, disabled-state
honoring, retry/backoff, reload/reconcile via `router.reload`, silent Undo
registration). This is the central refactor: today that logic lives inline in
`TimeBlock.vue:toggleCompleted` and must be **extracted into a shared
completion controller** so the two surfaces cannot diverge.

## Algorithms

### Active-block selection (reuse, do not reinvent)
The indicator's active block = `findCurrentBlock(effectiveBlocks, nowMinutes,
nowDate)` **AND** the returned block has `is_completed === false`. Because
`findCurrentBlock` already returns `null` off-today (nowDate null) and applies
the half-open `[start,end)` window + `(start_time, sort_order)` overlap
winner, no second selection policy is written. A completed block that still
contains `now` yields neutral (filter on `is_completed`); toggling it back to
incomplete re-activates it (reactive recompute from Inertia props).

**Null-guard before delegating (do not skip):** `findCurrentBlock` types
`nowMinutes: number` (non-null), but callers hold `nowMinutes: number | null`
(and `nowDate: string | null`) off-today. `activeUnfinishedBlock` must
therefore return `null` when `nowMinutes === null || nowDate === null`
**before** calling `findCurrentBlock`, mirroring `Schedule.vue:537–539`. A raw
pass-through is a TS type error; at runtime `null` numerically **coerces to
`0`** (not `NaN`) in `findCurrentBlock`'s `start <= nowMinutes` comparison, so
an unguarded off-today call would silently treat "now" as minute `0` (00:00)
and match the first block — a wrong active block, not a visibly broken one.

### Progress ratio (new pure util, near scheduleTime.ts)
```
startMinutes = timeToMinutes(block.start_time)
endMinutes   = timeToMinutes(block.end_time)
duration     = endMinutes - startMinutes
if (!Number.isFinite(duration) || duration <= 0) -> null   // fail closed → neutral
elapsed = nowMinutes - startMinutes
ratio   = clamp(elapsed / duration, 0, 1)
```
Return `null` on zero/invalid duration (caller renders neutral, never
NaN/Infinity). `progressPercent = Math.round(ratio * 100)`. Recomputed on
every `nowMinutes` tick (wall-clock re-sample, no accumulation → immune to
sleep/throttle drift). Exact start minute → 0 %; exact end minute →
`findCurrentBlock` already excludes it (half-open) → neutral.

### Derived indicator state (in the composable, all computeds)
- `active` = activeBlock !== null && progressRatio !== null
- `progressPercent` = derived as above (0 when neutral)
- `completing` = the shared controller's `saving`
- `errorState` = generic boolean from the controller (no block data)
Off-today / gap / future / ended / completed / invalid-duration all collapse
to `active === false` via the two guards above.

### Slice 2 — Shared completion controller (the anti-divergence refactor)

**Instancing model (CRITICAL — read before writing code):** `useBlockCompletion`
is a **per-call-site factory composable**, *not* a singleton. Each call returns
a **fresh, independent** state bundle `{ saving, errorState, generation,
toggleAbort, setCompleted, complete }`. The mutation state (`saving`,
`errorState`, `generation`, `toggleAbort`, and the mid-flight-captured
`blockId`/`scheduleDate`/`blockTitle`) is inherently **per-surface**: today each
`TimeBlock.vue` instance owns its own refs, its `is_completed` watcher gates on
*this* row's `saving`, and its `block.id` watcher aborts *this* row's in-flight
chain. `TimeBlock.vue` therefore calls `useBlockCompletion()` **once inside its
own `setup`** (N rendered rows → N independent instances); `Schedule.vue` calls
it **exactly once** for the PiP path. The anti-divergence guarantee is
**shared logic module, isolated per-surface state** — the retry loop,
generation-guard, abort-on-supersede, and undo-push code live in one module so
they cannot drift, but every call site holds its own reactive state so per-row
spinners and the abort-on-list-reshape invariant (issue #21) are preserved. A
single shared instance would collapse all rows' `saving`/`generation` into one
and regress the timeline-checkbox concurrency behavior `TimeBlock.test.ts`
guards — do **not** build a singleton.

**Accepted gap (cross-surface concurrency):** because per-surface state is
isolated *by design*, the timeline row and the PiP indicator for the *same*
block do **not** cross-abort — a near-simultaneous Complete from both surfaces
issues two `PATCH is_completed=true` writes and two (silent) `type:"toggle"`
undo entries. This is intentional and low-impact: both writes converge on the
same terminal state, both undo entries are `silent:true` (no toast), and the
scenario requires completing one block from two surfaces within the retry
window. Not fixed in this feature; cross-surface coordination would violate the
per-surface isolation invariant above. Noted so the implementer does not
"fix" it by reintroducing a singleton.

**Outcome contract (CRITICAL — needed by the TimeBlock rewire):** `setCompleted`
must let the caller distinguish three terminal outcomes so `TimeBlock.vue` can
correctly own its optimistic `displayedCompleted` flip/revert:
- `"success"` — a write in this chain resolved `ok`; undo pushed, `saving`
  cleared.
- `"failure"` — retries exhausted while this chain is still the newest
  (`generation` unchanged); generic `errorState` set, `saving` cleared, block
  left re-completable.
- `"superseded"` — this chain was aborted or a newer chain bumped `generation`;
  the composable **bails without touching any state** (does not clear/revert
  `displayedCompleted`, does not set `errorState`). The optimistic value must be
  left for the newest chain to reconcile.
`setCompleted` resolves to this `"success" | "failure" | "superseded"` union (in
addition to exposing the `saving`/`errorState` refs). `TimeBlock.vue`'s
optimistic revert runs **only** on `"failure"`, never on `"superseded"`.

## Privacy & accessibility invariants (enforced by tests)
- Never insert block title/category/date/exact-times into the PiP document —
  including hidden nodes, tooltips, `aria-label`, `data-testid`, error copy,
  or the PiP window title.
- Bar: `role="progressbar"`, `aria-valuemin=0`, `aria-valuemax=100`, rounded
  `aria-valuenow`. Complete control: keyboard-focusable, generic accessible
  name, visible focus style. State not conveyed by color alone. Respect
  `prefers-reduced-motion`.

## Lifecycle (must hold)
`closed --user click--> open/neutral|active`; `open/neutral --block starts-->
open/active`; `open/active --block ends|completes--> open/neutral`; `open/*
--manual PiP close--> closed`; `open/* --main app unmounts--> closed`;
`closed --user click--> open/*`. At most one indicator window; feature-detect
`window.documentPictureInPicture`; never auto-open on load; do not persist an
open preference that bypasses user activation.

## Out of scope
Native Dock progress, menu-bar/tray app, App Badging, any block-metadata
display, per-second countdown / smooth animation, running after the app
closes, auto-open without user activation, mobile live-activity, Firefox/
Safari parity beyond graceful feature detection, backend/polling changes.
