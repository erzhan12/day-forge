# Feature 0079 — PiP status window restyle

Restyle the always-on-top Document Picture-in-Picture status window so that
**in a block** and **in a pause** are distinguishable without reading the text.
Window management, size, placement and the data layer are out of scope.

Source design: option `5a`, section "Ход 5 · PiP-окно статуса" of
`Планировщик - варианты улучшений.dc.html` (mock not in this repo).

## Decisions taken before implementation

| Question | Decision |
| --- | --- |
| Active state shows the block title + category colour, reversing the 0066 privacy invariant | **Reverse it.** Tests, `RULES.md` and `.claude/rules/project.md` updated to record the narrower rule. |
| Mock frame is 320×64; `requestWindow` asks 280×60 and "don't change size" is out-of-scope | **Keep 280×60.** Padding comes down from the mock's `12px 14px` to `9px 11px` so both rows and the 9px gap fit unclipped. |
| Public Sans / IBM Plex Mono are not loaded anywhere in the project | **System fallback only.** Named first in the stack with `system-ui` / `ui-monospace` behind them; no third-party CDN request from a PiP document. |
| Mock's `mm:ss` / `h:mm:ss` countdown | **Rejected after review.** Keep the timeline badge's `formatRemainingMinutes` copy (`18m left`). The seconds clock built for it (`useNowSeconds`) was removed with it — see "Why there is no seconds clock" below. |
| Mock has no close control, but the shipped window had an in-PiP × | **Drop the ×.** The PiP chrome already has a close button. This narrows the explicit-close list to the header Hide (see `RULES.md`). |

## What shipped

### Frame (both states)

`#17181A` surface, `1px solid #2A2D31`, radius 12, column flex with `gap: 9px`.
Exactly **two `.fi-row`s and one `.fi-track`** in every state, so a block
boundary never changes the window height. No pure white, no pure black. The
window renders **no control of its own** — the PiP chrome's close button and the
schedule header's Hide are the two ways out.

### State A — in a block

Row 1: 3×14 `.fi-rail` in the category colour with a matching glow, title
(Public Sans 13/600, `#ECEAE6`, ellipsis), spacer, `18m left` countdown (mono
13/500, `formatRemainingMinutes`). Row 2: 5px `.fi-track` on `#2A2D31` with a
category-coloured fill at `elapsed / duration`, `role="progressbar"`.

### State B — in a pause

Row 1: a two-bar pause glyph (`.fi-pause-glyph`, two 3×11 CSS bars mirroring
the active state's rail, plus an `.fi-sr-only` "Pause" — a literal `||` reads
as two pipes in a mono face and is nonsense to a screen reader), `→`,
next-block title, spacer, minutes until it starts — all `#8E9299`.
Row 2: dashed track
(`repeating-linear-gradient(90deg, #3A3E44 0 6px, transparent 6px 10px)`) with a
solid `#8E9299` fill at `elapsed pause / pause length`. **No category colour and
no `#ECEAE6` anywhere in this state.**

Edge cases:

- **No measurable pause origin** (nothing has ended yet today, e.g. before the
  first block): `pausePercent` is `null` → dashed track renders decoratively,
  with no `progressbar` role and no fill. The countdown still ticks.
- **Day finished**: row 1 is the pause glyph plus `· day finished`, row 2 is an
  empty dashed track. `isDayFinished` fails closed — see below.
- **Off-today** (viewing another date): the pre-existing neutral `—` +
  screen-reader "No active block", now with the same two-row frame.

The mock's labels are Russian (`ПАУЗА`, `· день завершён`). The word ships as a
glyph, and `· day finished` in English to match the rest of the app.

### Why there is no seconds clock

An intermediate revision rendered the countdown as `mm:ss` and added a
`useNowSeconds` composable to drive it (one sample yielding both
`nowSeconds` and `nowMinutes`, since block selection on a minute clock plus a
countdown on a separate seconds clock would disagree by up to 59s at a
boundary). Both were dropped when the countdown went back to the timeline's
`18m left` copy: with a minute-granularity label a 1Hz tick changes nothing on
screen, and one second moves a progress fill by well under a tenth of a percent.
`useNowMinutes` remains the only clock. Do not reintroduce a second timer
beside it.

### Why `isDayFinished` is stricter than "no next block"

`nextBlockAfter() === null` is also true for an empty day, for malformed times
(it fails closed), and while sitting inside a completed final block. Claiming
`day finished` in those cases would be wrong, so `isDayFinished` additionally
requires a non-empty day, every block parsing, no inverted block (`end < start`),
and every block having ended. Everything else falls back to the neutral `—`.

### Category colour: mock vs app

The mock specifies `oklch(0.72 0.12 250)` / `0.75 0.12 150` / `0.78 0.12 75` for
`work` / `life` / `other`. Those exact values exist only in
`frontend/src/utils/categoryColors4a.ts`, which **nothing imports** — the real
timeline resolves colour through `getCategoryColor()` (theme-aware hex, e.g.
`work` = `#3B82F6`), and the app's categories are `work` / `personal` / `health`
/ `other` plus user-defined ones. The PiP therefore uses `getCategoryColor` so
its rail can never disagree with the block it mirrors; the rendered blue is more
saturated than the mock's. Confirmed with the user before shipping.

`tests/scheduleFocusIndicator.test.ts`.

## Deviations from the prompt, carried deliberately

- The **error state** keeps its `data-state="error"` outline and `Retry` chip.
- The window is now **dark-only**; it previously followed the system
  `Canvas`/`CanvasText` pair.
- The **countdown copy** is the timeline's `18m left`, not the mock's `08:20`.

## Manual smoke (browser)

Chrome-only, needs the full dev stack. Open the indicator from the schedule
header and confirm: in-block rail/fill colour matches the timeline block; at a
block boundary the window switches state with no height change; after the last
block of the day it reads `▮▮ · day finished` over an empty dashed track;
the window shows no button of its own and the PiP chrome's close still restores
with one Show click.
