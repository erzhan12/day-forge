# Deterministic Auto-Placement for Untimed AI Add Actions (Chat)

Day Forge currently forces the model to invent a start time for every `add`, so a
chat request like "add LeverX" with no time lands at a fabricated "earliest free
slot" (e.g. `06:00`) — in the past. This change makes **untimed create placement
deterministic and backend-owned for the multi-turn chat apply path only**: forward
from the current local time for today, otherwise from the user's schedule-window
start, using a 25-minute default duration, 10-minute clearance around other blocks,
and the existing 5-minute grid. Explicit `add`s (both times supplied) are unchanged.

**Scope decision (important).** Auto-placement applies **only to chat**
(`_apply_actions_sync` → `plan_mutations`). The **draft** generation/apply path is
left unchanged: drafts shape a whole day from history/templates and already emit
explicit HH:MM for every `add`; relaxing the add schema there would make the model
drop template times and pack 25-minute slots, destroying the intended day shape, and
routing `_apply_draft_sync` through `plan_mutations` would silently clamp near-edge
explicit adds that `_apply_add` → `_check_day_window` currently 400-rejects. Draft
`add` therefore continues to **require** both `start_time` and `end_time`.

### 1. Red: write failing tests first (in this order)

**1a. Planner + helper unit (pure, no LLM/schema path):**

   - Empty today: `plan_mutations(empty, [untimed add], earliest_start=time(10,5),

   - Today clamp: the persisted block never starts before `earliest_start`.
   - Custom duration: `duration_minutes=30` → 30-minute block.

   - Gap after a neighbour: placement may start exactly 10 min after it, not earlier.

     accepted explicit creates, and accepted updated positions; **a rejected update
     reverts to its original interval and that original still blocks placement**
     (`mutation_planner.py:598-616`); deleted blocks free their space.
   - Sequential multi-block: two default untimed adds on an empty day with an explicit
     `earliest_start` (state it — e.g. `time(9,0)`) become `09:00–09:25` and
     `09:35–10:00`, preserving action order and exactly 10 min between them. (Do not
     rely on the `06:00–23:00` `DEFAULT_WINDOW` implicitly.)
   - Chronological-order note: each automatic add searches forward from the **common
     base** against current occupancy, so with **unequal** durations a later add may
     legally occupy an earlier gap the first add skipped. Add one test pinning this
     deterministic behavior so it is a documented decision, not an accident.
   - `no_slot`: a fully occupied/padded window yields no create diff, a skipped outcome
     with `reason_code="no_slot"`, no conflicting ids, and no directional suggestion.

**1b. `earliest_start` view helper (pure):**

   - Exact-grid instant (`10:05:00`) → `10:05` unchanged.

## Edge cases
- Empty day today: start at the later of the rounded current time and window start; no
  artificial 10-min gap from the window edge.
- Fully packed day: `no_slot`; never overlap, shrink duration, or search backward.
- Block near window end: accept only if the full duration fits; else `no_slot` (no
  midnight cross).
- Invalid duration: rejected at schema validation before planning.
- Very large valid duration: `no_slot` via minute comparison, no wrapped `time`.
- Past/future schedule: `earliest_start=None`, search from window start; the "never in
  the past" clock rule applies to today only.
- Current time before window → window start; at/after window end → `no_slot`.
- Legacy intervals partly outside the window: clamp only their padded occupancy; do not
  mutate the blocks.
- Same-batch deletes/updates: occupancy from the accepted final candidate; removed and
  rejected positions reserve no phantom space; a rejected update's reverted-original
  interval **does** reserve.
- Exactly 10 min of clearance is valid (half-open intervals; padded intervals may touch).
- Chat model omitting times when the user *did* give a start is prevented by prompt prose
  only — there is no backend signal distinguishing user-requested vs backend-chosen
  placement; documented accepted limitation.

## Out of scope
- The entire **draft** generation/apply path: unchanged; drafts keep emitting explicit
  HH:MM for every add and are never auto-placed.
- Changing behavior for explicit adds with both `start_time` and `end_time`.
- Auto-relocating explicit-time adds that conflict or fall outside the window.
- Per-action gap overrides or user-rule overrides of the fixed 10-min gap.
- Backward/earlier search, cross-day placement, or overnight windows.
- Changing update/move directional-suggestion behavior.
- Persisting duration/gap fields on `TimeBlock`; DB schema changes.
- Backfilling existing user-authored Rule rows.
- Frontend changes beyond the single scheduling-policy prose update.
- Changing draft locking, empty-schedule preconditions, rate limiting, audit behavior,
  or draft status transitions.
- Switching provider integration from JSON-object mode to strict structured outputs.
