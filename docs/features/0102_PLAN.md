# 0102 — Refine the block just added (issue #226)

## Goal

A short follow-up such as "в 14:00 на час, рабочая" or "at 14:00 for an hour, work", sent right after a successful add with no pending question, must update the block just created instead of being blocked by the replay guard or turned into a second add.

## Changes

1. `backend/ai/implicit_add.py`: a time (`HH:MM`, optionally after `at`/`в`) or `for`/`на` duration fragment after an assistant reply is sent to the provider unchanged, not prefixed with "add".
2. `backend/ai/prompts.py`: the chat prompt tells the model to resolve such a fragment to an existing block and emit one update with its `task_id`, changing only the requested fields; ask when the target is ambiguous; never add a copy.
3. The replay guard is unchanged: a duplicate add is still rejected, not converted into an update.
4. Tests: implicit-add unit tests for attribute fragments and for fresh titles after an apply; chat view tests for refinement without a duplicate and for a provider that still tries to re-add.
5. `RULES.md`, `docs/api.md`, `docs/REFACTORING_FINAL_AUDIT.md`, Playwright chat scripts and `tasks/` updated.
