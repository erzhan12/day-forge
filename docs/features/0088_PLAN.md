**0088 — Daily export API and personal read-only token**


Implement GitHub issue #288: backend daily Markdown generation, `GET /api/export/daily/{date}/`, and a personal token managed in Settings. Tokens authorize only export reads. MCP servers and query-string tokens remain out of scope.

Current contracts to preserve:

- `frontend/src/utils/dailyExport.ts::formatDailyExport` and `frontend/src/utils/scheduleTime.ts` define formatting, ordering, and duration behavior.
- `DailyExportDialog.vue` uses an initially empty, component-local optional note. It does not read `DailyReview.notes`. HTTP exports therefore return an empty note and omit the Markdown `note:` section.
- `backend/schedules/views.py::_read_schedule_page` captures the owner’s schedule and ordered blocks in a read transaction and returns `None` when rows are missing; first-use creation lives in `_create_schedule_page_rows`/`schedule_view`. Export reads must never call that bootstrap.
- `FrontendVersionMiddleware` permits headerless GETs but rejects explicitly stale `X-Frontend-Version` values. `InertiaIdentityMiddleware` checks `X-Schedule-User` only on unsafe methods. Preserve both behaviors and existing CSRF protection.

Implement each numbered slice with **red → green → refactor**: write tests first, run the focused tests and observe the intended failure, implement the smallest passing change, then refactor and rerun. Existing compatibility tests may already pass.
