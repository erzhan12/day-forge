# 0073 — Rules priority badge shows 0-based rank (top = 0 = highest)

## Context

The Rules list (`Settings → Templates & Rules`) renders each rule with a numeric
badge. Today the badge prints the **raw `priority` integer** (`RulesList.vue:218-220`
→ `{{ rule.priority }}`), so the top (highest-priority) rule shows the **largest**
number (e.g. `7`). Users read this as "7 = low priority" because the common mental
model is *0 = highest*. This is purely a **display** mismatch — the code already
treats a higher `priority` value as higher priority everywhere and is not changed
here:

- `backend/templates_mgr/models.py:103` `Meta.ordering = ["-priority"]`
- `backend/ai/views.py:103,715` `.order_by("-priority", "id")` (AI prompt feed)
- `frontend/src/components/RulesList.vue:96` sort `b.priority - a.priority` (desc)
- `bumpPriority` up = `priority + 1` (higher number = higher priority)

**Goal:** the badge displays the rule's **rank from the top of the list**, 0-based
(`0` at the top = highest priority, incrementing downward), instead of the raw
`priority` value. Top-of-list remains highest priority — only the printed number
and its tooltip change. No backend, API, AI-prompt, ordering, or `priority`-field
semantics change.

## Scope (single file + its test)

- `frontend/src/components/RulesList.vue` — the `.priority-badge` span.
- `frontend/tests/RulesList.test.ts` — badge assertions.

Out of scope: backend, `ai/`, the `priority` field/API, `TravelRulesList.vue`,
reorder logic (`bumpPriority`/`swapRules` unchanged), any change to *which* rule is
highest.

## Change

`RulesList.vue` already exposes the render index: `v-for="(rule, idx) in localRules"`
(`:154`). `localRules` mirrors `props.rules`, which the API delivers ordered by
`-priority` (highest first), so `idx === 0` is the top/highest-priority row.

1. Badge text: `{{ rule.priority }}` → `{{ idx }}` (`:219`).
2. Badge tooltip: `:title="`Priority ${rule.priority}`"` → a rank-oriented,
   convention-clarifying title, e.g. `:title="`Priority rank ${idx} — 0 is highest`"`
   (`:218`). Keep it a plain string title; no new i18n surface.
3. Accessibility: ensure the badge conveys "rank, 0 = highest" (via the `title`
   above; add an `aria-label` mirroring it if the badge is otherwise unlabeled).

Behavioural invariants preserved:
- Row order is unchanged (still highest-priority first); only the number differs.
- Equal-`priority` rules keep deterministic order (API `-priority, id`); `idx`
  yields distinct sequential ranks by render position — acceptable.
- Reordering with the up/down arrows still changes the underlying `priority` and
  re-renders; the 0-based `idx` recomputes so the moved row shows its new rank.
