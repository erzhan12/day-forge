# 0086 — Prefer tight windows for untimed adds (issue #260)

## Context

An untimed chat request, `add block "Write report"`, should use the available window before `Standup` when the block fits without the default gap.

The issue’s repro is: local time **10:03**, `Standup` **10:30–10:55**, and the default **25-minute** duration. The expected placement is **10:05–10:30**, instead of **11:05–11:30**.

Feature 0067 introduced symmetric neighbour padding before forward placement ([0067_PLAN.md:267](docs/features/0067_PLAN.md:267)). This change makes that gap a preference within the initial window while preserving later placement behavior.

## Decisions (agreed)

1. **Scope:** change untimed chat `add` placement in the `auto_creates` loop after the overlap fixpoint. Timed adds, updates, draft generation, and the frontend remain outside this feature.
2. **Gap preference:** try the full default first. If its result does not end at or before the initial window's right boundary (the start of the first occupied block after the base, or the day-window end when no block follows), retry that initial window with **10 → 5 → 0 minutes**. Reduce padding **symmetrically around both neighbours**. This treats spacing consistently when either neighbour prevents placement. In the repro, zero padding permits **10:05–10:30**, touching `Standup`.
3. **Placement within a tight window:** preserve a successful full-gap result exactly. For a reduced-gap result, choose the latest feasible grid-aligned placement within that window, leaving spare whole-grid minutes before the new block.
4. **Forward floor:** leave `_earliest_start` unchanged. Today uses local time rounded up to the five-minute grid; another date uses the day-window start. Never move the block before that floor.
5. **Later search:** if the block cannot fit in the initial window even at zero gap, retain the original forward-search result with the **full default gap**. Do not propagate the reduced gap into later windows.
6. **Day-window end:** when no upcoming block bounds the initial window, use the day-window end. Do not invent a gap from the day boundary; existing neighbour padding may still shrink.
7. **Compatibility:** preserve `no_slot` outcome semantics, action ordering, replay handling, and deterministic placement. Explicit `start_time`/`end_time` adds remain untouched, consistent with the issue #185 precedent.
8. **Issue #258:** configurable gaps are outside scope. Derive retry levels from the default-gap value and `GRID_MINUTES`, descending through smaller grid multiples to zero. Compute them **per call** from the module attribute `AUTO_PLACEMENT_GAP_MINUTES` (not as a module-level tuple), so `test_gap_retries_derive_from_default` can monkeypatch the default and so a later per-user value (#258) can be passed in. Do not hard-code a three-element retry list or introduce a setting.
9. **Documentation:** describe the gap as a preference in the chat prompt, API contract, and relevant repository documentation.

## Design / algorithm

Keep `find_slot` and its directional behavior unchanged. Implement the preference selection within the planner’s automatic-create path.

1. **Retain existing preparation.** Use the accepted candidate state after the overlap fixpoint. Preserve the duration, common base, action order, and oversized-duration rejection.
2. **Identify the initial window from raw occupancy.** Inspect intervals in deterministic chronological order, with end time and ID as tie-breakers. The first interval extending beyond the base bounds the window at its start, capped by the day-window end. If that interval covers or starts at the base, the initial window is empty. Intervals ending exactly at the base do not occupy it.
3. **Run the existing full-gap search first.** Rebuild full-gap padding from raw candidates and call `find_slot` forward as today. Retain its result as the fallback.
4. **Accept an initial-window full-gap result unchanged.** If the result ends at or before the initial window’s right boundary, use it immediately. Preserve the existing earliest-start preference in this case.
5. **Retry only the initial window.** For each smaller gap, rebuild symmetric padding from raw intervals. Keep padding arithmetic and window clamping in integer minutes.
6. **Place reduced-gap candidates against the right boundary.** Determine the latest permitted end `E` as the minimum of the day-window end and the upcoming neighbour’s start minus the trial gap (the preceding neighbour’s right pad needs no separate arithmetic — the overlap test below rejects it). Round `E` down to the five-minute grid and subtract the unchanged duration; call the result `S`. Reject the trial if `S` precedes the forward floor. Check **exactly one** candidate, `[S, S + duration)`, against all trial-gap padding: either a direct half-open overlap test (`duration_minutes` is already schema-validated as a grid multiple, so nothing is lost versus `find_slot`’s own guard), or `find_slot(S, S + duration, "later", ...)` with **`desired_start = S`** and the window end clamped to `S + duration`, so it can only return `S` or `None`. Never call `find_slot` from the base for a trial: a walk from the base can return a start earlier than `S` (e.g. `test_reduced_gap_leaves_spare_grid_minutes_before_block` would wrongly get 10:05–10:30 ≠ `S` = 10:10 and fail the level). A trial is **successful only when the accepted interval starts at `S`**. Accept the first successful gap level (Decision 5: no reduced gap leaks past the next block).
7. **Handle grid residue explicitly.** A neighbour imported at an off-grid time cannot always be touched exactly. Use the latest grid-aligned end before its padded boundary; never round into the neighbour.
8. **Restore full-gap behavior on failure.** If no reduced-gap candidate fits, use the saved full-gap result. If that result is absent, emit the existing `no_slot` outcome. Do not shrink duration, search earlier than the floor, or relax later windows.
9. **Insert raw boundaries only.** Preserve interval validation and final-state overlap validation, then add the accepted candidate. Recompute occupancy and the initial window for the next automatic create from the same common base.

Correct the stale “SOLE overlap guard” comment while retaining the validation it overlooks at [mutation_planner.py:910](backend/ai/mutation_planner.py:910).
