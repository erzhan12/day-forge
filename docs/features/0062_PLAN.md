# Issue #168 — AI Quick-Input Chips Send Immediately

## Context

The 4a quick-input chips currently copy their prompt into `draftInput` and focus/autosize the textarea. Change the shared `CommandBar` behavior so selecting a chip immediately submits that text through the existing `handleSubmit()` → `submitTurn()` path.

This applies automatically to both `dock` and `sidebar` variants because `ChatSidebar` mounts the same `CommandBar`. No `ChatSidebar.vue` change is required.

## Technical requirements

- A chip click must submit immediately without requiring Enter.
- The chip text must overwrite and discard any unsent textarea draft.
- Chips must remain visible but become natively disabled whenever `inputDisabled` is true, including `isProcessing` and injected `scheduleDisabled`.
- The handler must also check `inputDisabled` before changing the draft, providing protection if an event arrives during a state transition.
- No second turn may be queued while processing.
- Submission must continue through `handleSubmit()` and `useChat().submitTurn()` so trimming, optimistic user history, input clearing, errors, rate limits, AI replies, applied-result chips, snapshots, and undo integration remain identical to typed submission.
- Do not add prefill preferences, modifier-click behavior, queues, or suggestion-hiding state.
- Blank-chip note: a whitespace-only chip would overwrite an unsent draft and then be dropped by `handleSubmit`'s empty-trim bail (`CommandBar.vue:143`), silently destroying the draft without sending. This is unreachable in practice — suggestions come from the saved `chat_suggestions` list and the backend rejects blank entries (PATCH validator `backend/templates_mgr/api.py:586-596`; `preferences.py` also drops blanks on read) — but the frontend `resolveChatSuggestions` (`frontend/src/utils/chatSuggestions.ts:12-17`) does no filtering, so rely on the backend invariant. A defensive `if (!text.trim()) return` in the suggestion handler is acceptable but optional; do not add draft-preservation-on-blank as new behavior.

## Phase 2 — GREEN: minimal implementation

### CommandBar handler algorithm

Update and rename `useSuggestion` to reflect submission behavior:

1. Receive the emitted suggestion string.
2. Return immediately if `inputDisabled.value` is true, without changing the existing draft.
3. Assign the suggestion to the shared `draftInput` ref, deliberately replacing any unsent text.
4. Immediately call and await `handleSubmit()`.
5. Let `handleSubmit()` recheck `inputDisabled`, read and trim the chip-backed input, clear it, reset textarea height, and invoke `submitTurn(text, props.snapshotBlocks, props.pushUndo)`.
6. Do not add a queue, alternate submission path, or suggestion visibility mutation.

Remove the old focus/`nextTick`/prefill autosize work from the suggestion handler. Remove the now-unused `nextTick` import if it has no other callers.

Focus destination after a chip send: the old handler called `inputEl.value?.focus()`; the new send-on-click path intentionally drops that explicit focus call (the chip, not the textarea, was the click target, and it disables mid-flight). This matches the typed-Enter path, which also does not re-focus. Do not add a refocus-textarea step — it is not required by the issue and would be new behavior; leave native focus wherever the browser puts it after the click.

Pass `inputDisabled` to the suggestions `ChatResultChip`. Keep the single template listener so dock and sidebar use exactly the same handler.

### ChatResultChip disabled wiring

Add an optional boolean `disabled` prop with a default of `false`.

Bind it to every suggestion button’s native `disabled` attribute. Native button behavior must prevent click emission, while the `CommandBar` handler gate remains defense in depth. Add a disabled visual state, such as reduced opacity and a non-interactive cursor, without changing enabled chip styling or applied-result rendering.

## Phase 3 — REFACTOR

- Remove names, comments, imports, and tests that describe suggestions as prefilling.
- Keep submission logic centralized in `handleSubmit()`; do not duplicate trimming, clearing, autosizing, snapshots, undo, or `submitTurn()` error handling in the suggestion handler.
- Confirm no changes are needed in `ChatSidebar.vue`, `useChat.ts`, or suggestion persistence. Existing `useChat` tests remain the coverage for optimistic user bubbles and normal assistant-response handling.
