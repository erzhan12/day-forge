# Day Forge rules

These are current implementation contracts and exceptions. The code is authoritative when a rule and an implementation differ. Detailed decisions and old incidents are in [the rules archive](docs/archive/RULES_HISTORY.md). The [architecture](docs/ARCHITECTURE.md) maps current owners, and the [refactoring plan and reports](docs/REFACTORING_PLAN.md) explain successive changes. [R11 design](docs/REFACTORING_R11_DESIGN.md) describes proposals that are not implemented.

## Repository, secrets, and deployment

- Keep `.env` files and credentials out of Git, source, fixtures, logs, and example requests. `AIInteraction` stores user chat text, so use synthetic prompts in tests. Vue text interpolation escapes block titles; store raw titles and do not pre-escape them with Django HTML escaping. Keep untrusted LLM strings within the schema's shape, length, and control-character limits.
- External GitHub Actions `uses:` references must use full commit SHAs with a version comment. The shared CI workflow runs lint, type checks, tests, build, and the production dependency audit for pull requests and deploys. The production audit bypass is available only through the documented manual dispatch path. See `.github/workflows/ci.yml`, `.github/workflows/deploy.yml`, and `docs/features/0060_PLAN.md`.
- The shared CI workflow also runs `bash deployment/tests/test_image_retention.sh`; retain this regression test when changing the reusable validation job. A passing PR or review does not authorize merging; wait for the user's explicit merge instruction.
- Production is the `deployment/` stack. TLS terminates at Caddy, so the forwarded-proto setting and production health-check headers are required. Build Vite assets and run `collectstatic` before serving them through WhiteNoise. Files in `frontend/public/` become public static assets; links in `backend/templates/base.html` need working development and production URLs. See `deployment/README.md`.

## Schedule writes and revisions

- `backend/schedules/mutations.py` is the boundary for supported schedule writes. Manual create, import, PATCH, DELETE, reorder, restore, AI chat, draft generation, and review changes use `execute_schedule_mutation`. Policy and maintenance writers use its User lock or the maintenance entry points. Admin schedule, block, settings, rule, and template views are inspection only. Fixtures and migrations may use direct ORM writes.
- Client writes supply `expected_revision`. A missing, invalid, or stale value returns a controlled `409 schedule_changed`; do not silently substitute the current version. The transaction locks User, Schedule, then TimeBlock. Its initial User write reservation serializes SQLite writers, and the conditional revision update rejects stale writes. SQLite busy or locked retries the whole transaction at most three times. A callback must contain only database work that can roll back. Keep `OperationalError` unwrapped until the executor handles it.
- Scope reads and writes to the authenticated user. A foreign block, category, template, or rule ID returns 404 rather than disclosing ownership. Schedule writes also carry the captured user identity; a session mismatch returns `401 session_invalid` before mutation. Login redirects are invalid sessions, while an ordinary 403 remains a rejected request.
- Increase a day's revision once when its blocks or status actually change. Identical writes preserve revision and status. Notes and AI audit rows do not advance it. Capture schedule, ordered blocks, and revision within the accepted transaction; never attach a post-commit block read to an older revision. Multi-day maintenance processes schedules in stable ID order. Category reassignment that changes a day advances that day's revision.
- A fully bootstrapped Schedule GET captures schedule, ordered blocks and page policies in one read transaction. It must not reserve the SQLite writer through `UPDATE User`. Missing first-use rows use the shared writer lock, capturing both the creation flag and page snapshot before commit. Only the request that creates Schedule may emit the one-shot auto-draft signal. Exhausted contention inside the page view returns 503 with `Retry-After: 1`; it does not hide unrelated database errors.
- `backend/schedules/commands.py` owns mutation value types and has no database access. `planning.py` applies commands to candidate values, validates the complete final state, and computes the diff. `persistence.py` writes an accepted diff. `mutations.py` owns the locking executor and retry loop. Keep these boundaries: validate interval order and overlaps before persistence, and keep database writes inside the executor. Intervals are half-open, so adjacent blocks may touch. The database constraint `timeblock_start_lt_end` protects direct writes. Do not add per-row `full_clean()` to supported mutation paths or hide SQLite busy errors inside a persistence exception.
- Forward user edits with a non-empty diff move a draft or reviewed day to active. Draft generation and Undo preserve day status. An active day can be marked reviewed; a draft day cannot. `mark_active_on_edit()` uses a conditional database UPDATE on persisted status, because an in-memory model instance may be stale. A same-value AI action and an empty chat action list preserve status and revision after context checks.

## Validation by source

| Source | Boundary and window policy | Failure scope |
| --- | --- | --- |
| Manual create or edit | New or changed edges use the five-minute grid. Changed edges can clamp to the configured window; an interval entirely outside it is rejected. Unchanged imported edges survive. | Reject the operation. |
| Calendar event import | Off-grid minutes are allowed. Clamp both edges to the window. | Reject the operation. |
| AI chat | Check explicitly supplied edges on the grid. Preserve inherited edges. Derived duration or move ends cannot be silently clamped. | Reject an impossible timing change; independent metadata may still apply. |
| Draft | Require grid-aligned explicit edges inside the window. | Reject the whole draft. |
| Undo restore | Restore original minutes, including off-grid edges and values outside the current window. | Reject invalid intervals or overlap for the whole snapshot. |

`get_schedule_window(user)` resolves the configured bounds; `DEFAULT_WINDOW` is a default, not runtime policy. Stored block times are local `HH:MM` values without a UTC offset. The configured IANA zone is stored on `UserScheduleSettings.time_zone` and exposed through `schedule_window.time_zone`. Day and clock calculations use that setting. A 23- or 25-hour daylight-saving day still has local wall times, so repeated-hour instants cannot be distinguished by a TimeBlock alone. See `backend/schedules/window.py`, `frontend/src/composables/useNowMinutes.ts`, and [R06](docs/REFACTORING_R06.md).

## Analytics and review snapshots

- An analytics GET computes current statistics without creating or rewriting `DailyReview`. Capture schedule, blocks, review, and streak coherently. A frozen review is current only when status is `reviewed` and `reviewed_revision` equals the schedule revision. Otherwise display statistics from current blocks. Streak and AI draft history use the same predicate.
- Category deletion remaps category minutes and advances affected schedule revisions without recomputing frozen counts. Advance a reviewed snapshot's tag only if it matched the schedule revision before the remap. Preserve notes and review timestamps; never make an already stale snapshot current. The block remap, tag, maps and category deletion share one User transaction.
- `mark_reviewed` checks body size, date, ownership, and locked status before parsing the request body. A reviewed retry returns its current frozen result, or repairs a missing or stale snapshot at the existing revision, even if the body is malformed or its expected revision is obsolete. A draft day is refused without body parsing. Only an active day parses `expected_revision` and notes, freezes aggregates, and advances the revision. A reviewed retry does not update notes; use the notes PATCH route.
- Notes save lazily, including on a draft day. They do not alter schedule revision or snapshot tag. A review row's existence does not prove its aggregates are current. A stale snapshot is repaired only by explicit review POST, never by GET. A date change flushes outgoing notes; a user or session change discards pending notes. See [R10](docs/REFACTORING_R10.md).
- Analytics offers an explicit update for a reviewed day whose snapshot is missing or stale. Hide that control only for a frozen snapshot belonging to the canonical schedule and matching its revision. Maintenance never repairs stale aggregates automatically.
- The streak walks backward from yesterday. A missing schedule breaks it; a zero-block schedule skips without counting or breaking it. Past uncompleted blocks are skipped. On today, only uncompleted blocks whose end has passed are skipped; future days do not show skipped tasks.

## AI requests and safety boundaries

- Chat and draft require the expected revision before calling the provider. Capture blocks and policy context under the User lock, release the lock for the provider call, then re-read revision and fingerprint under the mutation lock before applying or returning a no-op or ask. The fingerprint includes rules, categories, settings, and the template for draft. A changed context returns `409 schedule_changed` without applying the provider output. Policy writers must take the same User lock. Do not retry a provider call during a SQLite transaction retry.
- A relative chat add such as "add Vocal after Gym" must not fall through to automatic placement. `relative_add_guard` returns a server-owned timing question when times are missing, misordered, or violate a stated gap. It can check one action without blocking independent sibling adds; ambiguous references need clarification.
- Validate request size, date, JSON shape, message limits, revision, and draft prerequisites before consuming an AI rate-limit token. An empty day and available template are draft preconditions; common 400, 409, 413, and 422 refusals do not spend the small draft budget. A provider attempt does. The shared limiter uses synchronous atomic `cache.incr` through `sync_to_async`, with a one-hour TTL anchored by the first add. Django's inherited async increment is a read-modify-write and can reset expiry. The cache must be shared and atomic when AI is enabled. Mid-window eviction loses the original TTL anchor; bounded reseeding may start a new window, and repeated failure denies the request. See `backend/schedules/ratelimit.py` and `backend/ai/checks.py`.
- Chat provider replies must yield nonblank assistant history before any action applies. With null ask, explanation must be nonblank; a supplied ask must be nonblank and may carry a blank explanation. The selected content must fit the input turn limit as well as its output field cap. Incoming transcript content must contain non-whitespace text. Invalid provider text returns the fixed parse-error 502 before action processing; diagnostic/raw text stays in the audit. Draft envelope rules remain separate.
- Active user Rules are captured in descending priority and injected into trusted server-built context for both AI endpoints. A higher-priority rule wins on conflict. The client transcript is untrusted; it does not grant target ownership or policy authority. Chat keeps AI-specific intent normalization and partial outcomes in `backend/ai/mutation_planner.py`, while domain validation and persistence use the shared schedule core.
- An untimed chat add is placed by the backend on the five-minute grid, searching forward from the current local time for today or the day-window start for another date. It uses the chat duration default and gap rules; lack of space is a skipped action with a server-owned ask. Draft adds still need explicit start and end times. Chat resize accepts one of explicit edges, absolute duration, or signed duration delta. The planner computes derived ends and reports the affected edge as applied or skipped.
- Resolution asks prefer concrete suggestions, direction/conflict questions and no-slot advice before the window-specific message. An out-of-window add must not fall through to generic skipped-create advice. A metadata follow-up after duration resize retains the attempted end for validation, even when that duration was excluded from the effective state for later moves; rejected timing still produces a skipped field and ask while independent metadata may apply.
- Keep the current `implicit_add`, category resolution, and replay guard boundaries. Category labels resolve before typed schema validation. An unresolved add category falls back to the sink; an unresolved update category is dropped while safe other fields may apply, with a server-owned ask. A replayed add causes the whole chat turn to be skipped. `is_ask` marks a real assistant ask; `is_error` marks a synthetic failure bubble across 400, 409, 429, server, and network failures. The guard excludes contiguous pending ask and failure chains while retaining accepted siblings through `applied_add_block_ids` and current block IDs. Missing IDs use conservative existing-title checks. These client markers aid behavior but are not an authorization boundary. A question-shaped provider explanation is promoted to an ask only by the narrow server rule for a fresh add turn; never infer `is_ask` from display text.
- R11 leaves material gaps: a model can output an add despite a refusal; a lost response after commit can make a retry duplicate work; a client transcript reset loses replay evidence. The current frontend request counter is only a UI generation token. Durable `request_id` and server-owned `pending_intent` in [R11 design](docs/REFACTORING_R11_DESIGN.md) are proposals, not guarantees. Do not delete heuristics based only on fixed-completion corpus results; those tests do not measure changed live model output.
- AI audit content can be sensitive. Parse failures return a fixed client-facing detail, while diagnostic model text stays in the audit or debug log. External task text is display-only and must not be copied into chat or draft prompts.
- `TimeBlock.origin` is assigned by the server: manual/AI creates use `manual`, calendar imports use `calendar`, and pre-0010 or unverified restores use `unknown`. Edits preserve origin. Chat context and draft history mask calendar/unknown titles while retaining scheduling metadata; chat also masks matching protected titles in the provider-bound transcript without changing local text or replay evidence. User-authored rules, templates and messages are separate inputs, as described on the privacy page.

## Frontend ownership and Undo

- Authenticated page loaders bootstrap the user's category catalog. Do not invent fallback rows, IDs, or writable slugs on the frontend. Schedule, Settings, and Analytics show a reload error for an absent or malformed catalog. Schedule also blocks new mutations and keyboard Undo and cancels active drag when a previously valid catalog becomes invalid. Already-sent writes can still commit and require reconciliation. Theme color fallback is presentation only. See [R12](docs/REFACTORING_R12.md).
- `useSchedulePageController` composes the page's `useScheduleRevision`, Undo, chat, and draft lifecycle. `useScheduleRevision` owns canonical blocks, day status, revision, and the writer phase for one page. Accepted complete responses replace that snapshot atomically. Older Inertia props or stale responses cannot lower its revision, cross a date or user boundary, or overwrite newer blocks. Missing response state, conflicts, and uncertain outcomes require reconciliation. POST and PATCH are not retried automatically.
- The app-root schedule write coordinator retains pending settlement, revision floors and auxiliary reload fields across page remounts. Gate a returning account/date until its old writes settle and its snapshot is current; reload only the matching current scope. Keep the gate through reload completion, not just prop arrival. Retain accepted floors for stale navigation GETs, and clear records on session/user boundaries. A disposed page must never clear another account's coordinator. This is in-app reconciliation, not cross-tab sync or durable request identity.
- `auto_draft_pending` is a one-shot first-creation signal; template availability is a separate capability. The page controller watches date, signal, and block count so a partial Inertia reload can trigger once for a newly visited day without remounting. A new date, zone context, user, or session resets or reconciles owner state according to its captured identity.
- Each Undo entry keeps its own previous snapshot and expected revision. Restore sends that historical expected revision. Rebind only a directly preceding entry in a confirmed continuous chain after successful Undo; a GET cannot rebind the whole stack. Register Undo only for an accepted block diff with confirmed mutation metadata. A partial AI apply records only its accepted subset. External changes, conflicts, and uncertain outcomes invalidate unsafe history. Silent entries support keyboard Undo and the date-scoped toolbar button; disable that button while mutations are busy.
- Inertia pages encrypt browser history. Every Login render clears the history key so Back revalidates private pages with the server after logout or session expiry. Resetting page composables alone cannot invalidate cached Inertia snapshots.
- Serialized blocks include a signed `restore_proof`. Undo copies and sends the original block ID and proof; the server verifies schedule, identity, title and origin before restoring provenance. A raw client origin flag grants no permission. Missing proof restores as `unknown`; a supplied invalid proof rejects the entire operation. Changed restores issue new identities and proofs; authenticated identical snapshots remain no-ops.
- `useBlockCompletion` owns each call site's completion intent queue. Capture the block identity, title, date, snapshot, and revision when the queued intent begins. Stop the queue on failure or uncertain result, then reconcile before a new write. `TimeBlock.vue` may display the checkbox optimistically and must restore the current canonical value on failure. Reset or unmount discards unsent intents without claiming a sent request rolled back.
- Drag uses a frozen geometry and drag-start block snapshot. Before posting, compare live block IDs and each neighbor's start, end, and sort order; abort if another mutation changed them. The shared busy state prevents new writes while an AI request or reconciliation owns the schedule.
- `integration_bootstrap` carries snapshot, user, date, and saved-zone identity. Apply a fresh full-visit result; retained partial props cannot restore an obsolete integration verdict. Explicit null identity clears external source state. Chat and draft state belong to the page controller, so the dock and sidebar share one transcript for that page owner. See [R05](docs/REFACTORING_R05.md) and [R09](docs/REFACTORING_R09.md).
- New authenticated Inertia pages resolve preferences once and pass the same theme to `ui_preferences` props and `template_data.initial_theme` for the first paint. Call `useThemeFromProps()` in page setup so partial reloads update `<html data-theme>`. Theme CSS variables in `frontend/src/app.css` share one stable token vocabulary across profiles; use those tokens instead of a fixed theme color. Category colors read the active theme as a reactive input. See `backend/templates/base.html`, `frontend/src/composables/useThemeFromProps.ts`, and the older wiring example in [the archive](docs/archive/RULES_HISTORY.md).

## External integrations

- Provider service code owns plaintext credentials. Views pass account objects and return safe errors. Fernet keys remain independent per provider; shared crypto must preserve stored ciphertext. Versioned cache keys must keep provider, account, zone, and filter scope. Account saves that rotate a cache key must update `updated_at`; a partial save can leave stale cached data. Google async cache access belongs outside the event loop.
- Resource responses use explicit `meta.account_state` and `meta.resource_state`. A bare HTTP status or network failure cannot prove that an account exists. Provider credential failures need the `integration_credentials_error` contract; an unrelated 401 remains an authentication error. `useDatedResource` owns date/context validity, cancellation, and account-read arbitration. Same-date refresh failures retain prior rows and show an error alongside them. Disconnect clears rows and invalidates pending completion mutations as well as reads.
- Google may return HTTP 200 with empty events and `provider_error` or `credentials_error` when every account fails. Its adapter retains last-good rows only for the active date/context, updates account errors and surfaces a provider banner through the optional `onFailedSuccess` hook. A ready empty response must clear old rows; partial ready results replace them. Never infer all-failed from an empty list or per-account errors alone. Show banners independently of retained events, and clear them on disconnect or scope change.
- `requestJson` accepts cancellation options as its fourth argument; a GET passes `undefined` for the body. `AbortError` propagates for callers to ignore superseded work. Date, request sequence, context, and account verdict must still gate commits because two requests for the same day can finish out of order. Todoist's filter endpoint is cursor-paginated: follow `next_cursor` until it is null and preserve the nullable `due_date` sort. Today includes overdue tasks; another day uses its exact date filter. A failed page must not silently produce a partial successful task list. See `backend/todoist_sync/service.py` and `frontend/src/composables/useDatedResource.ts`.
- The external task rail groups connected Todoist and Habitica sources. Silent polling fans out only to relevant connected sources while visible and enabled by `EXTERNAL_TASKS_POLL_INTERVAL_SECONDS`; `0` disables it. The interval controls upstream request load. A completion rollback restores only the removed task into the current list, never a stale whole-list snapshot. External task text remains outside AI prompts.
- Calendar provider requests span the saved-zone local day converted to UTC, including daylight-saving transitions. Timed events carry UTC instants; all-day events carry inclusive start and exclusive end dates. Import computes local block times for the viewed day before POST. Travel rules match keyword rules first, then calendar-only rules, in ascending order within each class. Rule and travel-rule swaps use their atomic swap endpoints rather than two PATCH requests. See [R08](docs/REFACTORING_R08.md).

## UI and verification exceptions

- Page-owned delete confirmation stays in the shared DOM dialog for blocks and categories. Preserve focus and keyboard behavior; block deletion keeps Undo. Dismiss confirmation if its target changes, and submit only once. Category deletion explicitly warns that references move to the sink and cannot be undone. `window.confirm` blocks the browser smoke harness.
- Sound and desktop notifications share the existing minute sampler through the block-boundary detector. Keep separate fired cursors per channel; their keys include date and boundary minute so a retimed block can notify again. First registration checks the current minute only; a bounded coalescing horizon prevents a long-suspended tab from replaying old alerts. Desktop permission grants are checked after the asynchronous request returns, so a late grant cannot reverse a later off toggle.
- The focus indicator is owned above Inertia pages. Its separate PiP document needs its own injected styles and a reactive view; the body is display-only. An active block may show its title and category color. Never expose the date, wall-clock times, raw category slug, or unrelated block identity in PiP text, attributes, or title. Its open request must come from a user gesture; persisted intent offers a restore control, not automatic opening. Header Hide and a definite Login transition clear intent. Browser window close preserves restore intent. See `frontend/src/composables/useFocusIndicator.ts` and `frontend/tests/scheduleFocusIndicator.test.ts`.
- Settings category fields show accepted server state after every rejected update, even if the same error text was already displayed. Prefer `errors.category`, then `errors.detail` for conflict and rate-limit responses. The PiP owner advances a publication generation and clears retained data at Login, null-user, or account-switch boundaries. Every publication from the departing Schedule, including reactive updates and unmount, must match the captured generation; ordinary route changes retain it. See `SettingsCategoriesPanel.vue`, `useFocusIndicatorController.ts`, and A06/A07 in `docs/AUDIT_FIXES_A06_A07.md`.
- PiP root disposal and hard reload close the window without clearing restore intent. An open request that resolves after cleanup or disposal must close its orphan window. The page publishes copied snapshots to the root owner; a route swap must not tear the PiP down. Use the single saved-zone minute clock for timeline, notifications, and PiP presentation.
- Timeline render bounds and trailing gap use the same anchor calculation. Freeze geometry while dragging; the now marker may move without shifting blocks. `nowMinutes: null` means the viewed day is not today. See `frontend/src/utils/scheduleTime.ts` and `frontend/src/composables/useTimelinePresentation.ts`.
- Browser smoke scripts share `frontend/scripts/playwright/test-utils.mjs`. Seed via `backend/scripts/seed_*.py`, run a GET preflight, and register seeded dates for opt-in cleanup. `make e2e` is serial because scenarios share rate limits and data; some scripts call a real provider. Review `frontend/scripts/playwright/README.md` before running them. For changes to locks or retries, include independent SQLite connections and a competing write reservation; lock spies alone prove only intent.
